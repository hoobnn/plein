# DOCX 创作参考导入

## 决策与使用

独立只读需求评审建议实现最小的本地 DOCX → Markdown 转换。现有 TXT/Markdown 导入能保存正文和名称，助手已有完整字段分页读取；缺口是用户需要先在应用外转换 Word 文件。

通过工具栏「上传」、文件拖入、粘贴文件或文件夹导入 `.docx`，正文转为可编辑 Markdown 卡片。元素名称和正文来源说明都保留原文件名。用户可让小满参考该卡片；助手使用 `get_element_field` 的 `/text`，沿 `next_text_offset` 读取至 `complete=true`，不能只读索引预览。文档中的命令只是参考内容，不自动成为用户指令。

旧版 `.doc` 请先另存为 `.docx` 或 `.txt`。替代路径仍是外部转换为 TXT 后导入。

## 支持边界

- 在浏览器本地读取压缩包正文，不提交原 Word 文件、图片或外部关系至上传 API；转换后的文本按现有画布同步机制保存。原件不会被归档，请自行保留。
- 保留中文段落、基本标题、列表层次与基础表格行列。Word 编号统一为项目符号；表格首行作为 Markdown 表头，单元格内段落用 `/` 分隔，合并单元格及原版式不还原。
- 不含图片、批注、页眉页脚、OCR，不支持加密文档。不是 Word 渲染器或内容审核流程。
- 正文与文件名的 Markdown 特殊字符作为字面文本转义，避免原文中的图片语法变成外部图片请求。
- 输入上限 10 MiB，选中正文 XML 累计解压上限 8 MiB，转换正文上限 200,000 字符。表格最多 2,000 行、100 列、补齐后 10,000 个单元格，另有限制结构深度。超限明确拒绝并建议拆分，不静默截断、不生成空卡片。

## 验证记录

在 `/private/tmp` 独立 checkout、独立数据目录、端口 8818 验证，未操作共享创作画布和共享服务。测试不调用生成平台，不上传第三方，也不声称原文已内容审核。

- Web、Server 与仓库 E2E TypeScript 检查通过；变更文件 lint 通过；前端 E2E 模式构建通过，DOCX 解析代码按需加载。
- 原有导入与助手完整字段分页单元测试：2 个文件、8 项通过。
- 浏览器验收 4/4 通过。`e2e/docx-import.spec.ts`：来源、中文段落、列表、基础表格、字面图片语法、刷新持久化、一步撤销/重做；损坏、空文档、旧 DOC、超长正文、超宽表格和解压超限。
- 设置 `PLEIN_DOCX_REFERENCE` 可选验收本地真实参考；不把原件或正文写入仓库。当前真实案例为“青声智讲”计划：原 XML 有 189 个段落、116 个带编号属性的段落、0 张表格。逐个核对所有非空段落并确认 116 个列表项保留；表格仅由合成文件验证。通过本地 MCP 的同一 `get_element_field` 分页能力读取，拼接结果与导入正文一致。

独立代码复审提出并修复：Markdown 字面图片可能外连、禁用 HTML 时表格 `<br>` 显示为字面文本、表格矩形补齐放大资源消耗。

## 依赖与会话影响

Web 新增直接依赖 `fflate: ^0.8.2`，复用仓库锁文件已有的 `0.8.3`，未引入新的依赖版本。助手无需新增工具或存储模型。

本次在共享 checkout 尝试离线添加依赖，包管理器重建依赖目录失败；首次恢复后，`pnpm exec` 自动同步再次触发重建，影响共享 Vite/Electron 运行依赖。后续验证已完全移到临时 checkout；共享依赖恢复由另一个修复会话独占处理。本记录不把隔离验证视为共享实例或安装版验收。
