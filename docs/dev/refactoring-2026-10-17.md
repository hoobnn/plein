## 覆盖率口径及门槛

`pnpm test:coverage` 对 354 个应用和公共包源码文件统计，包括没有被测试导入的文件。只排除测试、类型声明、生成代码及测试辅助文件；没有排除 UI 或桌面入口来提高数字。HTML 报告在仓库 `coverage/index.html`，机器可读汇总在 `coverage/coverage-summary.json`。

| 指标       | 已覆盖 / 总数   | 覆盖率 |
| ---------- | --------------- | ------ |
| Lines      | 11,572 / 22,186 | 52.15% |
| Statements | 13,141 / 26,270 | 50.02% |
| Branches   | 8,131 / 19,134  | 42.49% |
| Functions  | 2,726 / 6,414   | 42.50% |

全局门槛为 lines 52%、statements 49%、branches/functions 42%，用于阻止当前基线回退。另对核心模块执行更高的门槛：

- 工作流三个实现文件逐文件要求 lines/functions 100%、statements 95%、branches 90%；调度本身当前四项均为 100%。
- `runs.ts` 要求 lines/functions 95%、statements 90%、branches 80%。
- 列表快照合并函数四项均要求 100%。
- 已纳入测试的五个桌面状态/桥接模块逐文件要求 lines/statements/functions 100%、branches 90%。

CI 与 `pnpm verify` 均执行覆盖率门槛，CI 显式安装 ffmpeg、fontconfig 和中文字体，保留报告 14 天。以临时目录及故意超过实际覆盖率的门槛检查过失败路径，命令按预期返回非零。提高门槛前应补足真实行为测试，不用排除业务源码或仅复述实现的断言抬高数字。

## 再次独立审查

重新对照 HEAD 审查所有待提交改动，服务端、前端、公共包与桌面端分别独立追踪调用链及回归测试。发现并修复 1 个 P2 调度问题：上游环与下游混合环共存时，沿第一条等待链直接摘环会先跳过下游，导致本应在硬依赖跳过后放行的软依赖节点也被跳过；依赖集合的插入顺序会改变执行节点集合。

停滞处理改用内部迭代 Tarjan，先处理没有其他未决依赖的终端强连通分量，再传播硬依赖跳过。新增上游硬环、软环及节点/依赖顺序排列回归，并以 12,000 节点长环验证不依赖递归栈。调度实现四项覆盖率仍为 100%。

修复后再次由另一位审查者复核算法，以独立传递闭包参考枚举四节点停滞等待图和顺序变化，共 405,000 个案例通过；这项证据只覆盖算法行为。其余范围未发现需要修复的实质问题。修复后的全仓 `pnpm verify`、构建和完整 65 项浏览器端到端测试重新通过。

## 尚未证明的范围

全源码单测覆盖率并未达到完整覆盖。主要缺口是 React UI（行覆盖约 12%）、Canvas 内核未触达的渲染和交互（约 38%）、桌面启动/更新/菜单流程（桌面整体约 29%）。浏览器 65 个流程另行验证，不并入上述 V8 单测数字，也不能替代所有异常分支。

测试中的 1 项跳过来自按 ffmpeg 字幕能力互斥选择的环境分支，保留原有条件。桌面测试使用 Electron 边界 mock；没有据此声称安装包及原生系统通知已实机验收。序列测试验证时钟与预览流程，未测得新的 UI 帧率或真实 AudioContext 切换指标。没有调用真实付费生成平台，也没有验证远端任务恢复服务状态。
