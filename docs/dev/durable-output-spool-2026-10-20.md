# 同步输出持久暂存

## 问题与合同

同步平台返回的文件曾以内联 base64 保存，超过 16 MiB 后只留下 dropped 标记。入库失败或进程退出时，字节可能丢失；恢复不能再次生成替代原结果。旧 dropped 记录继续保留并明确不可恢复，不补造远端 ID 或重新提交。

新调用使用宿主内部 `RecordedOutput.spool`。绑定包含 owner、job、call、attempt 和输出序号，文件位于独立 `job-outputs`，不放入启动会清空的 tmp。先持久化 writing 绑定，再排他写临时文件、同步文件、原子发布并同步目录，最后记录 ready。恢复只采用绑定一致、大小和 SHA256 均通过的最终文件；writing 状态也可找回已经发布的 ready 文件。

入库只读取暂存副本，失败不消耗唯一字节。done 记录持久化后才删除暂存；未引用的孤儿经过宽限期清理，活跃引用不按 TTL 删除。发布、入库、清理与维护共享 DataActivity 租约，备份不能切在文件和数据库引用的更新窗口中。

完整备份包含引用中的暂存文件；缺失或损坏的 ready 文件拒绝生成“完整备份”。writing 尚未落盘可以作为失败事实保留。恢复同样检查 manifest、绑定、大小和哈希。字幕审计历史只用于追溯，不作为当前暂存活引用。

公开 `ProviderCallResult.outputs.data` 合同保持一致：内部 done 用已入库资产映射代替大字节 JSON，恢复时经 AssetStore 校验归属和完整性后还原。URL-only 和字节输出的最终资产都必须有效，文件丢失或损坏不能返回完成，也不能回退生成。

## 验证边界

测试使用本地假平台与受控故障，不调用真实付费平台。覆盖 17 MiB 返回、入库失败、登记失败、磁盘满注入、绑定隔离、符号链接、截断与同长篡改、备份恢复。真实子进程 SIGKILL 覆盖 ready 已发布但 journal 仍为 writing、以及开始 ingest 前两个窗口；恢复后累计 submit 为一次。

这些证据支持 macOS 本地 AssetStore 的进程中断恢复，不证明断电耐久性、S3 接管或跨机器恢复。平台字节尚未返回或尚未持久化时的硬退出仍只能保留提交未知；客户端关联 ID 不提供平台幂等保证。
