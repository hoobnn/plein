# 原生输入与多行历史验收

本轮修复 `bb4eef6` 关闭一个实际的原生文本历史问题：在窗口焦点切换或菜单编辑路径中，多行替换的撤销／重做可能清空正文或重复插入内容。独立 Electron 合同的原构建六项全部失败，修复构建六项全部通过。更新包的前台手动复验因 Mac 锁屏尚未完成，不能将程序化合同写成物理输入法验收。

## 实际观察与原因

使用当前源码构建独立 `Plein Acceptance`，身份为 `com.ikuyu.plein.acceptance`，与正式版分开，禁止自动更新；启动明确使用 Mock 平台并关闭助手。旧验收目录的任务预检为 60 成功、3 失败，没有非终态任务。本轮只新建“原生输入与窗口验收 · 1021”测试项目，不修改既有制作内容或已安装的正式版。

原生窗口已实际完成项目命名、添加文本节点，粘贴中文、英文、组合重音、emoji、双向文字和长行，正确显示未找到的 `@` 引用。短 ASCII 和纯中文替换可撤销、重做；把选区替换为 `A\nB` 后，撤销恢复旧值，重做却清空文本，直接点击“编辑 → 重做”也复现。这里的 `\n` 表示真实换行。

记录输入与属性赋值顺序后确认：`PromptBox` 在失焦时选择文档快照显示；原生编辑已经修改文本框、本地草稿尚在同步时，旧快照会被写回原生控件，破坏多行编辑历史。只给草稿加 `flushSync` 的候选仍失败，已放弃，没有进入提交。

修复让文本框始终显示本地草稿；原有 layout effect 继续同步远端文档、更名、撤销及光标位置。没有替换原生撤销栈、改写画布历史或强制同步整个 React 树。

后台窗口最初的截图及辅助树停在“正在打开工作区”；资源请求正常，把窗口置前后首页与控件均正常显示，因此未将其判为产品启动卡死。后续进入画布、命名和编辑均通过原生工具实际操作。

## 可复现合同与回归

新增 `apps/desktop/scripts/edit-history.contract.mjs` 与最小 preload 夹具。合同使用本机 Electron 44.8.0、隐藏窗口、独立临时用户目录、自动分配端口的 Mock 服务，加载真实应用，覆盖菜单、主进程、页面内命令三条路径的选区替换和追加，共六种情况。检查正文、文档参数及元素数量，不使用系统剪贴板；该夹具不替代正式 preload / IPC 的安全合同。

先生成 `--mode e2e` 构建，再从仓库根运行：

```sh
PLEIN_NATIVE_HISTORY_DIST=/绝对路径/e2e构建目录 \
PLEIN_NATIVE_HISTORY_REPORT=/绝对路径/report.json \
apps/desktop/node_modules/.bin/electron apps/desktop/scripts/edit-history.contract.mjs
```

也可在 desktop 工作区使用 `test:edit-history`，仍需指定构建目录。未修复构建退出码 1，六项失败；修复构建退出码 0，六项通过。[原构建报告](../benchmarks/2026-10-21-native-history-baseline.json)、[修复报告](../benchmarks/2026-10-21-native-history-fixed.json)均保留。

普通浏览器的多行替换／追加、剪贴板粘贴、撤销重做及刷新保留新增两项，原构建就能通过，明确不将其冒充原生缺陷的检出证明。原生合同补齐了这个覆盖缺口。

## 仍待完成

旧验收诊断实例已精确定位后以 SIGTERM 退出，执行句柄以 0 结束；这不冒充通过原生菜单退出。随后启动干净 `bb4eef6` 的独立验收包，仍使用 Mock 模式、关闭助手，日志确认专属数据目录和服务就绪。正式版保持运行。

Mac 之后锁屏，原生工具两次明确返回锁屏，解锁请求仍待回复。修复包的前台菜单／快捷键复验、窗口调整和重启后实际界面仍待检查；没有保存或宣称不存在的修复后截图。此前 Ctrl-Space 和按键注入也没有证明真实输入法候选会话；实际 IME、物理触控板、多屏、休眠与长时连续使用均保留待验。

本轮新增计费调用为零。完整结构化证据、报告哈希及包来源见[验收记录](../benchmarks/2026-10-21-native-history-acceptance.json)与[包构建记录](../benchmarks/2026-10-21-native-history-package.json)。
