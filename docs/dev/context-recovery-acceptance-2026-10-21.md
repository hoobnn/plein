# WebGL context 恢复与真实闲置期验收

## 确认的问题与修复

现有按需渲染引擎移除了 Pixi 的每帧自动绘制。Pixi 在收到 `webglcontextrestored` 后会重建 GPU 系统，但引擎没有因此请求新一帧，静止画布仍为空白，必须等待其他内容或视角变化触发绘制。

在 Apple M4 Pro／Metal 上主动丢失并恢复 context 后，独立检查点探针等待 15 秒仍未恢复像素；随后将 context 丢失／恢复加入已有 RGB 和半透明实际像素用例，原构建在主画布恢复后的像素断言稳定失败。回归不人为 `preventDefault`、不替换渲染器或主动重绘，依赖产品本身处理恢复事件。

修复在 WebGL 引擎初始化后监听恢复事件并请求下一帧，销毁引擎时解除监听。Pixi 自身先完成 context 系统重建；WebGPU 路径不增加此监听。保留原有 Shader、uniform、GPU context 与纹理所有权，不修改文档或重试模型任务。

首个独立探针错误地比较了弹窗覆盖区域，把预览丢失 context 时的可见变化误归给主画布；失败报告单独保留。修正后改为检查主 context 未丢失、关闭弹窗后的原画布像素和文档保持，之后才确认上述真实空白问题。没有将错误探针当作产品缺陷证据。

## 不缩短真实时间的闲置期检查

修复前冻结构建 `0ed1e1d` 在同一 Metal 浏览器上，以千媒体／34 张素材执行以下独立验收，没有改计时器、GC 策略或过期配置：

- 主画布移出全部媒体，检查点继续使用共享纹理；实际等待 35.115 秒后 34 张仍被引用，预览像素差异为零，无加载／卸载错误。
- 关闭检查点，保持主引擎打开；约 30.160 秒后闲置纹理回收完成，owner 仍为一个、活动租约为零、已加载和卸载中纹理归零。
- 返回主画布，重新加载 34 张素材，1000 个预览恢复，完整元素和连线快照不变。

此检查补齐真实 30 秒闲置回收与重新加载的时间边界；不把约一分钟等待写成原生长时或休眠恢复验收。全部使用隔离服务、Mock 平台与现有冻结素材，调用费用为零。

## 最终验证与边界

修复提交 `90498a0`。核心 11 文件／81 项、canvas-core／Web／root 三处类型与定向格式／lint 通过。真实 Metal 的三项密集画布和像素用例通过；软件生产构建与开发 StrictMode 的同一组 14 项检查点／像素生命周期均通过，无失败、跳过或 flaky。没有为简单监听器再添加重复实现的模拟单测，也没有因本次改动重复全仓覆盖率或性能基准。

最初的千媒体探针在修复构建再次执行，检查点和主画布均收到实际恢复事件，并自动恢复到原像素；两处像素差异比例均为零，文档未变，不依赖点击或缩放触发新帧。由 Pixi 处理丢失事件，探针不代替产品调用 `preventDefault` 或重绘。

[结构化记录](../benchmarks/2026-10-21-context-recovery.json)保留原构建失败、各运行模式报告、真实闲置时间和源码／构建哈希。[失败现场](../benchmarks/2026-10-21-context-before.png)为主画布 context 恢复后黑屏；[通过后的最终画布](../benchmarks/2026-10-21-context-after.png)属于用例末尾恢复的新画布，视角不同，不冒充同视角设计对照；恢复阶段本身以实际像素断言及独立探针的原像素比较证明。

此处主动使用 `WEBGL_lose_context` 扩展，不等同发生过真实驱动故障、系统休眠或原生窗口切换。Mac 本轮仍明确报告锁屏，实际 IME、物理输入、原生长时和外部环境项目仍待验。
