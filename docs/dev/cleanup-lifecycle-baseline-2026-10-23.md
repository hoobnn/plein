# 第三批清理：E2E 目录、性能基线与批次输入快照

2026-10-23，接续[清理审计](cleanup-audit-2026-10-23.md)剩余的 5–7 项。此次保留既有架构与提交前检查；没有安装或同步共享依赖，没有提交或推送。

## 改动与边界

| 范围         | 完成的行为                                                                                                                                                                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E2E 临时目录 | 配置加载只生成路径，`--list` 不建目录。独立服务监护在启动时独占创建，确认后端进程组停止后才删除；显式 `PLEIN_E2E_DATA` 和创建冲突的目录均不认领、不删除。保留自定义服务命令、auth/dev 环境及 worker 数据路径。                                            |
| 中断与失败   | IPC 断开或原 Playwright CLI 进程消失都触发停止；普通退出先发送信号，超时升级为整组 `SIGKILL`。不把 shell 领进程退出当作全部后端退出，已关闭文件与 socket 的僵尸进程不阻碍回收。                                                                           |
| 性能 CI      | 同一 runner 顺序构建和测量两个独立检出；默认选择候选提交之前最近的 `v*` tag，可指定 tag/commit。基线必须匹配且干净，不能与候选为同一 commit。统一使用候选的 harness 和 Chromium，产出两份报告及比较结果；基线缺失或不兼容即失败。                         |
| 性能报告     | `formatVersion=2` 必须为 `complete`；真实媒体 ClipboardData、规范化实际 demo 文档均有 SHA-256。完整 11 项指标各保留至少三轮原始样本，校验数量、合法值和中位数；过滤场景、缺样本、未知版本或环境差异均拒绝比较。拖动与运行场景校验实际 12 元素和 20 节点。 |
| 批次快照     | 在第一次 `await` 前同步复制 Y.Doc，每个存在的目标只 `inspect/prepare` 一次；缓存判断、kept 判断和批次记录复用同一 `Inspection`。成功和异常都释放副本，执行时仍检查 live 文档和批准输入，保留 force/rerun、旧结果兼容和未知提交保护。                      |

比较门槛保留原规则：相对退化超过 50%，同时首预览/引擎就绪超过 100 ms、媒体完成超过 200 ms 或每帧 JS 超过 2 ms 才判回退。环境、实际夹具、轮次与完整指标集必须一致；历史 formatVersion 1 报告不能直接作为新门禁基线。用法与输出路径见[开发约定](../../CONTRIBUTING.md)。

- 性能报告合同 27 项、基线选择及真实比较 CLI 子进程 13 项通过；缺轮次、缺样本、环境不符和刻意回退均产生非零退出。
- E2E 生命周期合同 10 项通过：成功、断言失败、启动退出、启动超时、只列用例、调用者目录保留、独占冲突、CLI SIGINT/SIGTERM、忽略 TERM 的后端及孙进程强制停止；检查了退出前目录仍存在及结束后 socket 释放。合同已接入 `pnpm verify`。

## 同机性能比较

在两个独立检出中，以当前候选 harness 顺序测量 `v0.3.1 / 94bf794` 与 `fcbbbd4` 加未提交清理改动。使用 Node 26.12.1、darwin/arm64、SwiftShader、1440×900，200 个元素、4 张唯一图片及真实视频/音频；冷热各三轮、全部五个交互场景通过。两边环境、媒体和 demo 摘要完全一致，11 项指标均有三轮原始样本；比较结果 `status=passed`、`baselineCompared=true`、回退项为 0。

本次为本地完整链路验证；CI 保留 1,000 元素、32 张图片，不把这次小夹具当作生产规模结论。测试故意带入 profile、跳过打开、过滤场景和错误 dist 的诊断环境变量，编排隔离这些开关后仍执行完整 11 指标。复用真实测量报告注入超阈值回退、修改浏览器环境和删除一轮样本，比较 CLI 分别 exit 1；原始报告 exit 0，没有为负向验证重跑浏览器。

完整原始样本、比较结果、负向 CLI 证据、覆盖率和 32 个代码/配置/测试文件的 SHA-256 一致性记录见[机器可读验收记录](../benchmarks/2026-10-23-lifecycle-baseline-cleanup.json)。本轮端到端测量没有观察到超过现有门槛的回退，也没有据此宣称快照复制提高了总批次速度。

完整验证使用 `HEAD fcbbbd4` 加明确清理路径的独立检出，APFS 克隆现有锁定依赖；该提交已包含先前完成的 Agent 功能。并行未完成的桌面更新改动及无关研究文档均未纳入快照。完整 lint 抓到新增 Node 合同注册返回 Promise 的问题，修正为 `void test(...)` 后重跑通过，没有关闭规则。

验收结束后已移除本轮两份临时 worktree 及其注册、依赖克隆、日志与 UI 测试产物；保留上述机器可读证据和工作区源码。

## 适用范围

服务监护在 macOS 实测，Linux 由后续 CI 验证；owner 自身被 `SIGKILL` 或机器崩溃仍不保证回收。没有按名称批量删除历史临时目录。副本文档的创建本身有成本；单次准备计数不能推导整个批次的耗时收益。SwiftShader 的每帧 JS 与打开耗时不是硬件 GPU 帧率，也不是付费平台或线上性能验收。
