# 即梦短剧画布：界面与工作流参考

调研日期：2026-10-26。对象为用户提供的[即梦短剧项目](https://jimeng.jianying.com/novel/detail/canvas?projectId=12998802275596&canvasId=13004612698380&overviewPippitAssetId=13002226212364)。通过已登录 Chrome 实际浏览、展开菜单、切换视图和进入已有分集编辑器，并对照 Plein 当前源码。本文是参考分析，不代表已实施的改造方案。

## 核心判断

最值得借鉴的是按创作阶段和当前对象组织功能：资产准备用列表与自由画布，镜头制作用脚本、预览和片段条，选中素材后才出现加工工具，AI 助手按需展开。用户主要面对角色、场景、镜头、片段和成片，底层模型及节点关系退到局部操作中。

Plein 已有画布、资产、分镜、镜头工作台、制作引导、配方、模板与序列能力。优先参考其界面组织和操作距离，复用现有数据与执行体系；不能因为即梦出现某个入口，就判断 Plein 缺少对应能力。

## 证据与边界

- 实际观察 CSS 视口为 1224 × 763，截图为 2448 × 1526；下文尺寸使用 CSS 像素。
- 初次画布显示节点 0；分集列表已有「第一集」。进入其编辑页后出现默认「片段 01 / 分镜 1 / 10s」，返回资产列表显示视频 1，回画布显示节点 2。未点击新增、生成、发送、应用模板或修改参数；这些变化发生在页面导航期间，是否由页面初始化或同步造成没有进一步验证。
- 展开已有折叠分组时观察到「保存中」。因此不能将本次浏览表述为完全没有服务端写入。未执行内容生成、素材上传、删除、合成、付费操作。
- 已验证界面、菜单内容及部分跳转；未验证真实生成效果、批量执行、费用结算、成片导出、长项目性能及多人协作。3D 导演台与多轨编辑器仅确认入口，未新建实体来验证内部功能。

## 1. 信息架构：两条工作线，三种主要工作表面

| 层级       | 实际观察                                                                     | 作用                                 |
| ---------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| 全局导航   | 最左 56px 窄栏：制作资产库、故事板；画布状态另有角色库、生成历史；帮助在底部 | 将阶段导航与局部工具分开             |
| 项目级设置 | 顶栏约 52px：项目名、风格库、比例、分享或合成、账户信息                      | 保留少量跨阶段入口                   |
| 资产工作区 | 顶部「列表 / 画布」切换                                                      | 同一项目在检索管理与关系编排之间切换 |
| 分集总览   | 集数、待生成状态、角色 / 场景数、分镜视频进度、编辑、批量                    | 先选择制作对象，再进入细节           |
| 分集编辑   | 左资产、中脚本、右预览、下片段条；助手另行展开                               | 把一次镜头修改所需信息放在同一屏     |

这里的「列表 / 画布」切换与资产侧栏里的「列表 / 宫格」不同：前者改变工作表面，后者改变资产集合呈现方式。Plein 的画布 / 故事板模式及侧栏画布 / 资产也有不同语义，后续设计需要明确命名，不能只照搬这两个词。

## 2. 自由画布布局

截图：`01-canvas.png`、`02-add-node.png`、`10-node.png`。

- 近黑点阵画布，浮层用更亮的灰阶与圆角区分，描边较克制，作品区域优先。
- 项目名、列表 / 画布切换、节点数位于左上；风格和全局比例位于顶栏右侧。
- 资产库浮在画布左侧，可收起、可调宽；初次显示宽约 340px，宽度控件范围为 240–408px。搜索、全集 / 单集范围、分组、标签共同服务于资产检索。
- 底部中央工具条负责添加节点、工具箱、教程、快捷键和指针工具。
- 左下视口工具条负责重置、连线显示、整理、角色场景显示、小地图、网格吸附、触控板 / 鼠标模式、缩放。实测外框高 36px、圆角 8px。
- 右下用短提示和「下一步」表达阶段推进：确认角色场景后进入分镜脚本生成。展开其他工具后可缩为小入口。
- 空画布提供角色、场景、3D 导演台、多轨编辑器、视频、图片、文本、音频八类入口，并提示双击画布创建节点。

值得保留的是「创建工具居中、视口工具靠角、阶段行动靠另一角」的分工。固定位置形成肌肉记忆；不应把所有功能塞进一个浮条。

当前窗口中，左侧资产面板遮挡了部分空状态入口；选中视频节点后，大生成面板又与底部固定工具条重叠。Plein 应按剩余可用区域布置空状态、面板和视口，而不是只按整个窗口居中。

## 3. 资产管理：全局资产与当前集上下文

截图：`07-asset-list.png`、`12-character-library.png`、`13-history.png`。

独立资产页面按角色、场景、3D 导演台、文本、图片、视频、音频、多轨编辑器分栏，并显示数量、搜索与出现集数筛选。角色和场景被说明为可应用到整部剧集的设定。

编辑器资产侧栏默认显示当前集，保留切换范围、分组、标签与创建入口；同一种资产不必为每个编辑表面重新管理一套。

从资产列表点击「片段 01」会返回画布并定位来源节点。若节点位于折叠组内，先提示「目标节点位于已折叠的分组中」，再提供「展开并定位」。这一点适合用于 Plein 的分镜、资产、候选与时间线互相定位：解释为什么暂时看不到目标，并提供直接动作。

AI 角色库另有年代 / 类型分类，以及性别、年龄、物种、体型、身高、发长、发色、气质筛选。生成历史按全部 / 图片 / 视频 / 音频及完成状态筛选；本项目当时没有符合条件的生成记录，因此未验证记录详情和失败恢复。

## 4. 镜头编辑：资产—脚本—预览—片段条

截图：`03-storyboard.png`、`04-episode-editor.png`。

分集总览提供新增一集、批量与单集编辑。编辑器通过面包屑保留返回分集总览的入口，顶栏显示模型、分辨率、风格、比例和「合成全集」。

编辑器主区域分成三个可调整区域：

1. **左侧资产**：检索当前集素材、创建或切换范围。
2. **中间脚本**：片段编号、引用资产与工具、带时长控件的分镜描述、生成按钮。描述提示示例把时间、景别、人物动作和光线写在一起，支持 `@` 引用素材的表达。
3. **右侧预览**：当前片段的独立画面区域；未生成时明确提示先填写内容。

底部是片段缩略图条与批量、智能预演、添加字幕、生成配乐、多轨编辑器入口。此处观察到的是片段条，不应当作已经验证了完整多轨时间线。

核心收益是改文案和看当前画面不需要反复开关弹窗。Plein 当前镜头工作台适合逐镜核对，但连续制作可以考虑让它成为独立工作表面，同时保留快速弹窗作为轻入口。

「与 AI 对话」入口可展开故事板助手；助手支持素材附件、技能、模型、分辨率和计价入口。实际生成没有执行，未验证其编辑能力与审批方式。

## 5. 节点编辑：操作围绕选中的素材出现

截图：`10-node.png`、`11-models.png`。

选中已有视频节点后，节点上方出现工具条，底部出现提示词与生成参数面板。视频空节点本身提供上传、素材库、图生视频、首尾帧生视频、参考视频复刻等入口。

| 工具分组 | 实际展开看到的入口               |
| -------- | -------------------------------- |
| 素材拆解 | 抽帧、解析、拉片                 |
| 画面优化 | 提升画质、智能抠像、光效、去字幕 |
| 音频编辑 | 音频分离                         |
| 基础剪辑 | 截取、裁剪、旋转、倒放、倍速     |
| 片段创作 | 片段重拍、向后延长               |
| 专业剪辑 | 在多轨编辑器中打开               |

只验证了菜单，未执行以上工具。菜单按创作意图分组，减少用户先理解某个底层节点类型的负担。

生成面板支持上传参考素材、素材引用、模型选择、分辨率、参考模式、运镜、更多设置与提示词优化。参数留在当前对象附近，避免经常往全局设置走。

折叠分组的工具条另有整组执行、解组、展开、背景色、添加到工具箱。可复用工作流由分组提升而来，这与 Plein 已有分组运行和模板保存方向一致。

## 6. 工具箱、风格与技能：三种复用层级

截图：`05-skills.png`、`06-style.png`、`09-toolbox.png`。

**工具箱复用流程。** 预设 / 个人分类、名称搜索、列表 / 宫格视图；当前看到角色换装、场景设定与一键多机位、局部重拍、场景氛围切换、角色设定与一键多视图、480P 一键超分。卡片用对比图或多视图示意，让用户先理解结果。界面明确提示应用后要补齐输入，不会自动生成。

**风格库复用美术方向。** 搜索、全部 / 真人实拍 / 2D / 3D 分类，提供无、自定义与大量示例。其全局入口清晰，但本次未选择风格，未验证影响已有节点还是仅影响新生成。

**技能配置复用阶段规则。** 按 AI 生成剧本、资产设计、分镜设计组织；当时前两项标注「即将上线」。分镜设计可见配置方案管理，说明明确区分「选择配置进行编辑」与「设为当前配置后应用」。这比点击某项就隐式激活更容易理解。

Plein 应区分：资产回答「使用谁 / 什么」，风格回答「长什么样」，模板回答「搭什么流程」，配方回答「如何填写或转换生成参数」，技能回答「按什么方法完成任务」。可以共享浏览外壳，不宜把这些概念并成一个万能库。

## 8. 不宜直接照搬的部分

- 不复制当前窄视口下的工具条遮挡与超宽生成面板。内容应根据可用区域重排。
- 不照搬较暗的说明文本。Plein 现有辅助文字对比度要求继续适用。
- 不把模型营销文案写入接口能力合同；保留按实际 provider 能力发现和校验的机制。
- 不照搬强制线性流程。Plein 允许从任意已有素材开始，下一步建议应根据项目事实变化。
- 不把字幕、配乐、3D 或高级剪辑因竞品有入口就设为必经环节。
- 不将生成成功等同采用或交付。Plein 现有候选、人工审片、技术检查和交付确认应继续保持明确语义。

以上为参考调研时的结论；调研阶段仅新增文档，没有修改产品实现或运行应用测试。

## 9. 首轮界面改进（2026-10-26）

用户随后授权改进，首轮落实以下范围：

- 镜头工作台扩大为窗口内的制作界面，宽屏显示本镜参考、脚本与候选三列，各列独立滚动；较窄窗口调整为两列与顶部参考条，再缩窄则纵向排列。标题、关闭入口与底部镜头条保持可达。
- 底部镜头条提供分镜图缩略图、镜号、计划时长、描述与当前镜头标记；上一镜／下一镜以及返回分镜表缩短连续制作路径。
- 同一次工作台内切镜会保留各镜尚未保存的字段。草稿不跨工作台会话持久化，不自动保存；来源已更新时仍保留草稿并阻止覆盖新版。原有只读、阶段身份、迟到响应、候选采用、生成清单和媒体回收机制保留。
- 空画布增加角色、场景、图片、视频四个快捷创建入口；复用实时节点目录与放置逻辑，只创建结构，可撤销，不发起生成。只读不显示创建入口，矮窗口和手机宽度保留原双击／Tab 入口。
- 使用现有设计令牌，未新增模型、生成合同或文档持久化字段。

主要实现为 `ShotWorkbench.tsx`、`CanvasStart.tsx`、`styles/storyboard.css`；使用说明见[创作与审片](../guide/creation-review.md)。

验证包含前端类型检查、E2E 构建、相关文件格式与 lint、4 项工作台模型单测，以及 16 项相关浏览器用例。浏览器覆盖 390 / 768 / 1224 / 1440px 工作台布局、12 镜切换草稿、协作版本冲突、候选与恢复行为、媒体释放、快捷创建与撤销、只读，以及 320–1440px 底栏可达性和空态避让。截图与运行证据位于 `test-results/creative-workspace-ui/` 和 `test-results/creative-workspace-layout-final/`。

初次测量的跨帧布局断言受弹窗进场动画影响，已改为同一帧测量并单独复查。原工作台 E2E 的旧「编辑分镜」选择器已对齐当前「详细卡片」入口，未降低候选与执行断言。

另有一项已观察到但未纳入本轮实现的既有问题：`canvas-footer-fit.spec.ts` 的「分行底栏下文本生成器仍完整可编辑」失败，当前 `Generator.tsx` 的节点下方编辑器固定 840px 宽，700px 窗口中越界并与底栏重叠。当前另一套 `generator-layout.spec.ts` 显式要求维持 840px 与固定节点下方布局；这两个验收口径冲突，本轮没有改写节点生成器的布局规则。最终相关用例运行明确排除此项，不声称全量 E2E 通过。

本轮为本地源码改进，未提交、推送或发布；没有真实生成平台调用。

## 10. 图片节点与媒体工具专项调研

### 图片生成面板的紧凑布局

实测可见生成面板宽 960px、高约 244px，位于节点下方，采用三个层次：

1. 顶部参考区：48 × 48 的添加按钮，提供本地上传和从即梦资产库选择；右侧放大入口。

没有点击任何生成按钮、应用裁剪、保存标注或执行宫格切分。页面显示的积分余额始终为 88；这只是 UI 观察，未查询账单，也未开展模型效果或加工输出验收。

### 1. 裁剪是画布上的图形操作

进入「画面编辑 → 裁剪」后，生成面板被裁剪控件替代，**原图上直接出现裁剪边框、拖动手柄、辅助线和像素尺寸**；图片下方是一条局部工具面板，包含取消、应用裁剪和比例选择。

比例包括自由、16:9、4:3、1:1、3:4、9:16。实际选择 1:1 后，尺寸显示由 1280 × 720 变为 720 × 720；取消后回到原图，未应用裁剪。

这比仅输入 left / top / width / height 更适合构图。Plein 可优先实现拖动框与数字输入同步，保留现有本地加工后端；不需要为了改善裁剪交互新增 AI 调用。

证据：`22-crop.png`、`23-crop-square.png`。

### 2. 标注与局部重绘是不同工作流

有图后「画面编辑」比空节点多出「标注」。它进入专门的画布编辑模式，工具条提供矩形、画笔、箭头、文本、橡皮擦、标记、实色填充框、颜色、撤销、反撤销、退出及保存。切换画笔后检查了界面，没有画线或保存。它服务于给图像添加说明，不能与重绘蒙版合并成同一概念。

「局部重绘」则会**新建一个位于原图右侧、引用原图的下游草稿**，并在草稿图面上提示“标记你想要修改的对象”。下方生成面板自动带入原图参考，并显示图 1、插入引用、移除参考等操作。本次新草稿默认显示 Seedream 5.0 Pro 和自动 / 1K，与原图片节点面板显示的 AnyCook、9:16 / 3K 不同。

没有绘制重绘区域或提交生成，因此只确认派生节点、原图引用和编辑入口，不推断蒙版算法、身份保持或模型效果。这个发现也意味着 Plein 后续重排工具时要明确“打开编辑模式”与“创建下游草稿”的区别，并保留原图和实际引用关系。

证据：`24-inpaint.png`、`31-annotate.png`、`32-annotation-brush.png`。

### 3. 镜头调节：示意图与参数并排

「视角与构图 → 镜头」打开节点下方的镜头调节面板，未直接新增节点或开始生成。面板左侧为球面网格与图片平面示意，右侧为水平、垂直和景别控件，下方有可开关的补充提示词、积分提示和生成按钮，并提供重置参数。

本次实际读取到水平和垂直的范围均为 −180° 至 180°，初始为 0°；景别使用五档滑杆，初始中景。这里的球面示意是在表达相机与图片的相对方向，不能等同已有完整 3D 场景、遮挡重建或精确物理相机。

Plein 可借鉴可视化方向表达与补充文本并存的方式，复用已有镜头控制草稿；后续必须区分移动相机和旋转人物。模型能否实现指定角度，仍需实际样片验证。

证据：`27-camera.png`。

### 4. 打光：光源方向与画面风格分开

「视角与构图 → 打光」打开光效面板。左侧提供透视 / 正面切换、球面示意、光源位置和水平 / 垂直读数；右侧提供亮度、六个快捷方位（左侧、顶部、右侧、前方、底部、后方）、硬光 / 柔光、暖色光 / 中性光 / 冷色光，以及补充提示词、重置和生成。

默认亮度显示为 25。只是查看了默认值与控件，没有验证实时调节对原图的视觉效果，更没有生成光效结果。亮度、方向、软硬与色温属于不同维度，Plein 若后续提供类似控制，应把这些参数分别表达，而不是全部塞进“电影感”一项风格中。

1224 × 763 视口下部分面板向下越界；临时扩大截图视口到 1440 × 1200 后才看清完整布局。值得学习的是参数分区，不是它的溢出行为。

证据：`28-lighting.png`、`29-lighting-tall.png`。

### 5. 扩图：先预览目标尺寸，再生成

扩图界面显示原图边界与扩展区域，默认 W:1.5x / H:1.5x，明确列出目标尺寸 1920 × 1080 与原图 1280 × 720。下方提供倍率、原比例及 4:3、1:1、3:4、9:16 入口和生成按钮。没有提交生成。

Plein 当前图片处理合同已有扩图，优先补足“原图相对目标画布的位置、扩展方向和目标尺寸”的可视化，避免用户只看到比例文字而无法判断会扩哪一侧。

证据：`30-outpaint.png`。

### 6. 九宫格生成与已有宫格切分确实独立

有图后「九宫格」展开的是配方集合：表情九宫格、多机位九宫格、剧情推演四宫格、角色脸部三视图、角色设定图、场景设定图、产品设定图、25 宫格连贯分镜、电影级光影校正、角色三视图，以及画面推演 3 秒后 / 5 秒前。菜单名称虽然叫九宫格，内部包含不同数量和用途的生成方向；不宜直接照搬这个总名称。

「宫格切分」才是对已有图的网格拆分：4 宫格（2×2）、9 宫格（3×3）、16 宫格（4×4）、25 宫格（5×5）和自定义。自定义展开一个格子矩阵，界面显示当前 3 × 3，可用空间选择表达行列组合；本次没有选择执行任何切分。

Plein 已有生成配方与本地宫格切分基础。可以把前者命名为“角色与分镜配方”，后者保留“宫格切分”；切分入口可增加矩阵选择和边界预览，不应让用户把切分当成再次生成。

证据：`25-nine-grid.png`、`26-grid-split.png`、`33-grid-custom.png`。

### 本轮进一步收敛的改进顺序

1. **先统一图片动作目录与分组**：同一动作只维护一份身份、适用素材、禁用原因与执行方式，工具条和媒体菜单共享，不再积累重复入口。
2. **先改善本地工具的可视化**：图形裁剪、尺寸读数与比例；已有宫格的矩阵选择与切分边界。复用现有加工能力。
3. **明确三类交互**：原图上的编辑模式、派生下游草稿、需模型生成的参数面板。执行按钮应与实际行为相符。
4. **再改构图、打光与扩图面板**：以示意图辅助已有参数与提示词，始终保留实际模型能力约束，不把控件当成效果保证。
5. **同时解决浮层空间**：按可用视口限宽限高，长参数区独立滚动，退出、取消和执行按钮保持可达。即梦的工具条和多个编辑面板都观察到越界，不能原样复制。

仍未验收：真实生成效果、图层分离／抠图／提升画质的具体执行流程与输出、标注保存格式、应用裁剪后的候选保留，以及宫格切分后的节点组织。为遵守本次只查看、不生成和不加工的范围，没有点击可能直接执行处理的入口。
