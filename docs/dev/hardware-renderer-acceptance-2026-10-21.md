# 实际 GPU 与连续进出验收

## 渲染器判定修复

本机默认 Playwright 无头运行器在 `PERF_RENDERER=hardware`、不额外指定浏览器可执行文件时，实际返回 SwiftShader；原基准仅按请求模式写入 `hardware`，仍生成 `status=complete`。因此这类报告不能算硬件验收，也不能用其长任务和启动耗时判断 Metal 性能。

现在硬件模式必须读到可识别的 GPU 名称；软件回退或无法辨认的通用名称立即报错。比较器也拒绝两份同样错误标注的历史报告。新增回归先在原实现失败，修复后六项通过；root 和 Web 类型、改动文件格式／lint 通过。实际复跑在首轮采样前退出 1，报告 `status=failed`，保留 SwiftShader 名称、错误原因和空的冷／热样本。

用完整 Chromium 的已安装可执行文件再次核对，实际得到 `ANGLE (Apple, ANGLE Metal Renderer: Apple M4 Pro, Unspecified Version)`，浏览器版本仍为 156.0.8078.4。后续硬件基准显式指定该路径，不改变全局浏览器或系统设置。

## 三十次连续进出

使用独立服务、Mock 平台、冻结的 `0ed1e1d` 产品构建和固定千媒体夹具，在同一个页面连续 30 次滚轮平移、缩放、退出和重进。每轮核对完整元素／连线快照、1000 个预览就绪、程序键不变；退出后 owners、租约、排队／进行中的加载、已加载及卸载中纹理均为零。每轮移除诊断持有的旧引擎引用，再通过 CDP 显式 GC 后记录堆与 DOM 计数。

30 轮全部通过，耗时约 73 秒；无运行时错误或 WebGL context 丢失警告，逻辑程序键均为 4。JS 堆从 19,694,716 增至 24,612,536 字节，最后十轮增加 164,692 字节；事件监听器由首轮 4156 降至 4143，之后保持。不能用这组观察证明堆内存完全无泄漏或长时间使用稳定。

此循环使用 SwiftShader，是超过常见 context 数量限制的重建压力与资源生命周期检查，不是 30 轮真实硬件交互，也不是几十分钟或数小时使用验收。夹具通过测试入口创建，平移缩放使用 Playwright 实际鼠标／键盘输入；不是物理触控板或 IME 测试。没有模型调用，没有修改安装版或用户制作数据库。

## 同一 Metal 环境的三轮对照

修复前冻结构建为 `bb4eef6` 产品代码，候选为 `0ed1e1d`；执行时 HEAD 是仅增加验收文档的 `aaabe05`，未提交改动属于验收工具。构建身份以原始报告 fingerprint 和本段产品来源为准，不以执行时 HEAD 代替产品源码。两批环境、夹具版本、1000 元素和全部指标集合经原比较器核对一致；没有拿 SwiftShader 数据作为 Metal 基线。

| 指标                | 原构建  | 候选    |
| ------------------- | ------- | ------- |
| 冷开首预览          | 571.3ms | 692.0ms |
| 热开首预览          | 175.4ms | 164.5ms |
| 缩放 JS／帧         | 4.617ms | 4.566ms |
| 拖动 12 元素 JS／帧 | 2.354ms | 2.255ms |

原比较门槛未触发；候选冷开变慢约 120.7ms（21.1%），热开只快约 10.9ms，不宣称稳定提速。两批各六次打开均 1000 个预览就绪；五类交互均无长任务。真实媒体用于打开；五类耗时场景使用既有演示夹具，另用密集画布 UI 场景验证真实媒体操作。

## Metal 显示与重建压力复验

完整 Chromium 的原有三项 UI 用例全部通过：千媒体框选／嵌套分组／拖动撤销重做及资源释放，1060 元素和 59 连线的实际连接／整理还原，上传 RGB 与半透明像素在缩放／检查点关闭／恢复新画布后的正确性。未改业务断言或产品源码；[像素恢复截图](../benchmarks/2026-10-21-metal-pixels-restored.png)及[整理截图](../benchmarks/2026-10-21-metal-dense-arranged.png)已人工复查。

随后在实际 Metal GPU 上执行同一 30 次循环，约 21 秒全部通过，程序键保持一致，文档及素材不变，退出后受管理纹理均归零；无运行时错误或 context 丢失警告。显式 GC 后 JS 堆由 19,680,844 增至 24,596,240 字节，最后十轮增加 234,592 字节。监听器由首轮 4127 增至 4143，后续无逐轮增长；DOM 计数由 13909 至 13965。这仍是快速重建压力验收，不能替代原生前台和长时间编辑。

工具修复为 `e30b345`；硬件模式空场景最终写报告边界另实际验证为 `status=failed`／`unobserved`，不会把没有采样的执行写成成功。调用费用为零，未升级或替换用户安装版。
