本版让内置智能体能撑住更长的对话：较早的对话会自动压缩成摘要，请求预算按模型的上下文窗口来定，工具也改成按需加载，把上下文留给对话本身。

## 新增

- **自动压缩上下文**：新一轮开始前，如果历史连同系统指令和工具定义超过请求预算的 60%，或已攒满 32 轮，小满会用当前对话模型把较早的轮次写成一份摘要，最近几轮原样保留。摘要记下你的目标与偏好、已建和已改的元素、做过的决定和未完成的事，之后每次请求都带上它。压缩期间对话里有提示，完成后「上下文管理」会写明压缩时间和轮数；完整对话仍保存在本地。
- **可调的压缩阈值**：「上下文管理」新增「自动压缩」选项，可以选关闭、50% 到 90%（默认 60%），也可以选「固定 token 数」直接填一个值（默认 150,000，范围 16,000–4,000,000）。设置按会话保存，新对话沿用该智能体上次的选择，调整不会重置上下文。

## 优化

- **按模型窗口定预算**：请求预算改为按模型声明的上下文窗口推出（窗口减去输出预留），大窗口模型能带更多历史；没有声明窗口的模型按 96,000 tokens，面板会注明「按默认预算」。平台报告了真实输入 token 后，会用它校准之后的本地估算。
- **工具按需加载**：每次请求只带一组核心工具，其余工具由小满查到后再加载，同一会话里一直可用。请求里的工具定义从约 4 万 token 降到约 1 万。Claude Code、Codex 和对外 MCP 的工具清单不受影响。
- **重置上下文一并清空摘要**：「重置上下文」现在也会清掉自动压缩得到的摘要和已加载的工具。

## 使用说明

自动压缩会多一次模型调用，按该模型正常计费；压缩失败时本轮照常进行，按预算省略较早的历史。每一步模型调用都会重发整段上下文，大窗口模型（例如 1M）按 60% 意味着每一步可能带着几十万输入 token，响应更慢、费用更高，建议给大窗口模型调低阈值或改用固定 token 数。摘要只是记录，不构成新的授权。

本版新功能已通过本地自动化测试，尚未在真实平台上逐项验收。
