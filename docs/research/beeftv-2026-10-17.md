# BeefTV 源码对照与 Plein 优化依据

观察日期：2026-10-17。BeefTV 固定源码 `cfbe1ffd83438ff6d0691a653041ee958a69dc84`，Plein 起点 `056dc4d`。研究按画布、执行、Agent、创作交互、素材与迁移六个子系统对照，优化交付按[十个工作包](../plan/beeftv-optimization.md)计数；不以模型、按钮或宣传名词数量衡量完善程度。

## 产品与架构判断

BeefTV 是 React、Go、Wails 与 SQLite 组成的本地单人创作工作台，覆盖生成、画布组织、媒体加工、资产复用与 Agent。Plein 以 PixiJS 场景渲染、Yjs 文档、Node/Hono 服务和 PluginHost 组织相近流程，已有更明确的输入快照、候选采用、局部返工与远端任务恢复合同。

可借鉴的是交互和资源治理的具体行为；没有浏览器对照数据支持替换渲染引擎、空间索引、语言或桌面框架。[BeefTV README](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/README.md)、[实施合同](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/docs/refactor/implementation-contract.md)是定位依据，源码和测试才用于确认实现。

## 画布与媒体

BeefTV 把视口、节点挂载、媒体预览请求和释放分开处理，使用预览 lease、并发限制、取消和最后释放回收。[预览服务](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/services/canvas-video-preview.ts)、[渲染模型](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/pages/canvas/use-canvas-render-model.ts)提供了可拆分的参考。

Plein 已有 RBush、增量裁剪、两档缩略图、按需帧渲染和单个活动播放器。起点的具体缺口是 renderer 默认高细节导致低缩放首载多请求、所有内容变化都刷新几何、离屏 body 常驻、全局纹理缓存缺少显式引用治理。Pixi 本身已有 Worker/createImageBitmap 解码，不能再把新增解码 Worker当作必要优化。

本轮保留 RBush 和 Pixi，增加共享纹理池及每个 Engine 的 owner。卸载只能发生在最后引用释放后；同 URL 卸载与重载需要串行。512 MiB 是纹理来源尺寸估算软预算，不代表真实 GPU 内存上限；活跃引用可以超预算并被观测。

## 测量与加载

[BeefTV 性能文档](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/docs/refactor/performance.md)明确区分数据处理基准与浏览器帧率，并记录 fixture、版本与环境。该项目的部分源码字符串测试也不能证明媒体已经呈现。

Plein 起点的冷开脚本复制了 demo 文档却没有上传对应媒体，等待引擎引用和一帧动画即可完成，不能证明首屏媒体成功。优化先修口径：资产真实入库，拆分引擎就绪、第一张可见预览和可见预览全部结束；失败数、加载数、驻留数均进入报告。软件渲染器结果单独记录，不当作真机 GPU 性能。

首页按需加载还必须切断间接依赖：主题常量从 canvas-core 独立子入口读取，首页快速开始只登记节点意图，编辑器再执行。预算检查沿构建 manifest 的实际静态依赖闭包计数，不能只看主入口 chunk。

## Agent 执行与上下文

BeefTV 保留业务轮次、操作回执、会话交换及有界画布读取。[canvas-read-view](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/agent-host/canvas-read-view.mjs)、[durable-session-owner](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/agent-host/durable-session-owner.mjs)、[operation store](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/backend/internal/operations/store.go)展示了这些边界。

Plein 起点跨轮只给内置模型用户/回复文字，工具结果按字符截断，图片被替换成不可见说明；会话 MCP 凭据跨轮复用，无法可靠辨别旧轮迟到请求。优化保留既有能力注册表和 PluginHost，增加完整 transcript、执行审批事实、有界分页、预算和不可变轮次。CLI 会话通过已有 resume 保留，进程和凭据按轮创建。停止只关闭后续操作；已提交生成仍由既有任务恢复管理。

Yjs 文档和 SQL 回执不是同一业务事务，本轮不承诺任意工具 exactly-once。历史记录不是新的授权，恢复中断不能自动重发未知调用。视觉仅按模型显式声明启用，mock 验证通路不等于真实模型审片验收。

## 创作交互

[参考条](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/components/canvas/canvas-node-prompt-panel.tsx)提供显式顺序、替换、键盘操作和预览；[提示词建议](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/components/canvas/canvas-prompt-optimizer-drawer.tsx)支持可编辑草稿；[图片预览](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/components/canvas/canvas-image-preview.tsx)和[对比节点](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/components/canvas/nodes/compare-node.tsx)支持近距离审片。

Plein 起点参考顺序取决于画布 y/x，整理可能交换首尾帧；提示词改写成功即回写；浏览候选立即采用。这些是本轮优先修正的用户语义。稳定顺序进入文档，预览/缓存/提交共享排序；草稿采用前核对基线；候选浏览仅改浮层状态，明确采用才影响下游。A/B 是审片工具，不另造持久节点类型。

分镜审核复用既有稳定 shot ID、展开同步、分阶段执行和恢复。默认批量补未完成，选中镜头可明确重新生成；提交未知或平台已受理的任务使用原任务恢复，不借批量按钮隐式重提。

## 素材与检查点

[BeefTV 素材库](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/pages/assets/index.tsx)支持跨项目媒体浏览，[版本历史](https://github.com/glanderness/BeefTV/blob/cfbe1ffd83438ff6d0691a653041ee958a69dc84/web/src/pages/canvas/canvas-version-history.tsx)提供版本预览与恢复。

Plein 继续区分媒体库存和角色/场景等语义资产库。库存以 owner+assetId 为准，来源索引覆盖文档、任务、资产库和检查点，可重建且不臆造已删除来源。删除来源不删除文件。

命名检查点保留创作结构、候选采用及安全运行证据，用独立 pin 保护素材。保存屏障同时校验新增时钟和删除集，因为纯删除不增加 state vector。恢复创建全新画布，内部对象关联保留，历史 job ID 重映射且不可执行。检查点及独有素材随 manifest v2 迁移，旧 reader 明确拒绝高版本，避免静默丢检查点。

## 证据边界

本报告依据固定提交源码和本地依赖审查。实施、单测、真实服务界面、性能测量与真实平台分别以[优化台账](../plan/beeftv-optimization.md)及验收记录为准。没有把 BeefTV 的自述、静态架构或本地 mock 转写为真实生成质量和跨平台运行保证。
