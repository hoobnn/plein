# 稳定生产落实与验收

## 范围与完成边界

2026-10-20 用户要求按 P0 → P1 落实，并与现有 BUG 修复会话协调。用户随后明确本轮只做不新增付费的验收。因此真实平台的新提交、主动重试及重复计费验证均不执行；本地故障注入与既有真实素材复用分别记录，不能替代新增生成稳定性证明。

本文件是执行合同，勾选项必须附当前版本证据。单片成功、单元测试通过或打包成功，都不能单独得出“能够稳定连续生产”的结论。

## 修改归属

| 范围                           | 负责人                       | 隔离与约束                                            |
| ------------------------------ | ---------------------------- | ----------------------------------------------------- |
| 画布、分组、3D 与现有交互 BUG  | 现有“测试并优化画布交互”会话 | 主工作树；不操作本轮制作窗口与付费任务                |
| 请求恢复与平台错误分类         | 主会话及请求安全子代理       | `production-request-safety` 隔离树；不改交互文件      |
| 桌面验收身份与运行状态隔离     | 主会话及环境隔离子代理       | `production-desktop-isolation` 隔离树；不重启生产实例 |
| 请求关联信息与补提交历史合同   | 主会话及合同评审子代理       | 先评审，后确定实施范围                                |
| 冻结、迁移、连续生产与证据汇总 | 主会话                       | 采用独立数据、依赖和构建目录                          |

所有子代理功能修改先经评审；集成前检查文件交集。不对主树执行 stash、reset、clean 或依赖重装。

## P0 门禁

- [x] `pending` 缺少恢复合同或 `fetched` 缺少可恢复字节时保留原 journal，阻止再次 `submit`。
- [x] MiniMax、Ark、Bailian 已发出的 POST 遇到 408/5xx 时保留提交未知；GET 轮询及明确业务拒绝保持各自语义。
- [x] 请求关联 ID 在网络发送前持久化；关联 ID 不宣称具备平台幂等能力。
- [x] 人工补提交保留原未知尝试及操作证据；新尝试成功不能抹除旧请求费用待核对状态。
- [x] 平台故障矩阵验证实际 `submit` 入口次数、原 journal 及恢复状态，不只断言错误文字。
- [x] 验收桌面具有独立 bundle ID、userData、单实例锁和清晰身份；验收环境禁自动更新。
- [x] 冻结代码、依赖、原生运行时、字体和 FFmpeg，记录版本与哈希；打包资源独立于开发服务器。
- [x] 真实双开及重启验证互不占用数据、端口、锁和更新状态。

## P1 门禁

- [x] 开始制作前显示当前账号能力与缺失授权；未验证能力不可显示为可用。
- [x] 复用原青声智讲素材，在同一服务实例内连续完成三个独立短项目；每次记录项目、时间、操作与成片证据。双人对话、动作连续性、强风格的新生成基线另列为未验证，不以本轮素材剪辑代替。
- [x] 每次成片完成完整解码、时长与音轨检查，并进行实际播放和字幕可读性检查。见下方当前验收报告（3 个短片在系统播放器回看；完整版在验收包内回看）。
- [x] 局部返工不重生成或丢失已采用结果；记录干预步骤及受影响范围。
- [x] 青声智讲 `.plein` 导入新数据目录，核对媒体哈希、候选结果和剪辑引用，完成再次合成；验证期间平台提交次数为零。
- [x] 同一冻结版本连续三次冷启动，任务和文件均能恢复。

同机新数据目录迁移不等于另一台机器验证。尚未执行的新付费生成、跨机导入及供应商计费对账在最终报告中单列，不以本地测试通过推定。

## 证据要求

零新增付费的本地验收入口为 `apps/server/bench/stable-production.ts`，必须提供 `PLEIN_ACCEPTANCE_PACKAGE`、新的 `PLEIN_ACCEPTANCE_OUT` 和 `PLEIN_ACCEPTANCE_FREEZE_ID`；媒体工具和字体通过现有 `PLEIN_FFMPEG_PATH`、`PLEIN_FFPROBE_PATH`、`PLEIN_SUBTITLE_FONT` 指向冻结副本。脚本固定使用本次单画布青声智讲项目，不冒充通用题材基线。报告包含同实例连续三个项目与独立子进程冷启动证明；安装包 UI 和双开另行记录。

每次验收记录冻结 ID、Git 基线及未提交补丁哈希、运行时与资源版本、独立数据位置、开始结束时间、真实提交次数、故障与恢复、人工干预、输出哈希和检查结果。原始证据放在忽略的独立验收目录；凭据和完整敏感配置不纳入文档、日志或提交。

首次失败即停止宣称该门禁通过，修复后使用新的冻结 ID 重验受影响门禁。达到本轮无新增付费验收范围后，报告剩余生产准入缺口。
