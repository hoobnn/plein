## 冻结合同与实现

- 节点为 `plein/shot-analysis@1`，`execution: 'job'`，单一 `video` 输入、JSON `analysis` 输出；通过 PluginHost 的媒体服务执行，未替代 Provider/PluginHost。
- 上限：输入 600 秒、512 MiB、最长边 4096、最多 100 镜头；单分析槽、总截止时间 10 分钟、临时输出预算 1 GiB。进入前核对真实文件与元数据；解码中核对时长/帧数，写出期间每 200 ms 检查预算，进程结束和入库前再检查。解码帧数另设 1,000,000 的内存边界。
- 首个实际解码视频帧 PTS 定义为零。扫描实际 PTS，关键帧按覆盖请求时刻的帧持续区间选取；`frame.at` 保存请求时刻，`actualAt`/`actualEnd` 保存解码帧的真实持续区间。人工切点可以落在低帧率/VFR 的持帧中间。
- 自动切点使用 FFmpeg 画面差异阈值与最短镜头过滤；人工切点严格递增且位于视频内部，不静默排序/夹取。人工区间不受自动最短镜头参数限制。
- 关键帧默认提取。可选视频片段固定 30 fps 重编码，每段至少 1/30 秒，时长误差最多一帧；更短区间明确拒绝提取片段，仍允许只提取关键帧。片段入库前必须 `hasVideo` 且正时长，并核对时长偏差；原音轨必须 `hasAudio` 且正时长。
- 原音轨是第一条源音轨，保留对白/音乐/环境声的混合内容；基于相同 PTS 原点裁切、补静音与对齐，不宣称分离人声/配乐。
- 清单严格验证 hash、MIME、ID 唯一、从零到 duration 连续覆盖、非空区间、请求/实际帧持续区间以及 notes 限额；损坏 JSON 不进入清单 UI 或本节点的强资产索引。

`params` 只保存执行选项及人工 `cutPlan`（源 hash + 切点）。清单存入节点结果，不回写 `params`，所以不会形成 manifest 自引用缓存键；结果匹配回归验证完成后输入仍新鲜。

## 界面与持久化

- 视频媒体工具新增“本地拉片”，创建并连好节点；多输出节点按所选实际 assetId 找源端口，报告重新处理也按 `edge.from[1]` 读取实际采用结果，不猜 primary。
- 清单界面支持检测、编辑切点、可选片段/原音轨、选择镜头、将素材归组入画布并一次撤销、查看历史以及显式采用。历史预览本身不采用，不发生成请求。
- 素材放入画布保留 `shotAnalysisOrigin` 的源 hash、区间和时间基准。选择动作绑定 engine、节点和报告 resultId；异步预检核对服务端实际输入并携带输入 hash，换画布/换报告后的晚回请求不重置新视图。
- 视频预览默认 muted、无 autoplay；关面板或换报告时 pause、清除 src 并 load 停止媒体解码。只读/锁定时可查看报告，不能编辑、运行、取消、采用或放入素材。
- 复用 SQLite NodeRuns 的排队、冻结输入、取消与恢复。作业中断后从冻结源/参数重新执行本地阶段；当前输入已变时旧输入产物只进历史待采用。
- manifest 的源/关键帧/片段/音轨使用专用扫描接入 `documentReferences`、项目包当前候选筛选、检查点及维护 GC。新清单不覆盖旧候选；当前/历史包分别带对应资产。

## 取消、截止时间与临时文件

所有分析任务共用一个可取消槽。等待中取消会移除排队项；执行中 FFmpeg 接受信号，必要时 1 秒后强杀并等 close。`ffprobe`、编码器/能力探测及入库衍生子进程使用仅 P08 启用的 `withMediaAbort` 上下文，SIGKILL 后等 close，避免探针挂起占住槽。

这个上下文使用任务自己的 `ffmpegAvailable`/`h264Cache`/`capsCache`；不会等待或污染其他请求的全局探测 Promise。无上下文的既有媒体调用保持原行为。AssetStore 的内容去重直接复用已有资产；各衍生生成使用独立 `.part` 文件，P08 的取消不终止其他请求。

分析临时目录为 `<dataDir>/tmp/shot-analysis-*`，正常/异常/取消最终删除，删除失败也通过嵌套 finally 释放槽。入库读取流同样可取消。已经入库但未发布的部分产物不强删共享内容地址文件，按普通未引用素材的保留/GC 处理。

## 独立复核发现与已落实修复

1. 主 Agent：低帧率/单帧镜头中点之后可能没有新 PTS。改为取覆盖请求时刻的实际帧；片段 trim 包含覆盖起点的前一帧并补足时长，保留请求/实际时间分离。
2. 主 Agent：极短片段可能生成空 MP4。新增 1/30 秒明确边界、UI 说明和入库前媒体有效性检查。
3. 恢复用例：NodeRuns 原先在没有 Provider 调用记录时重新准备输入，导致本地作业重启误读新源。公共修复仅限 `execution: 'job'` 且无 capability 时复用已冻结输入；付费节点首提交前的预检和批准语义保留。
4. `p01_baseline`：普通 `probeMedia` 没有信号会阻塞取消。补入限定 P08 的取消上下文及挂起探针故障测试，同时防止 rm 失败泄漏槽。
