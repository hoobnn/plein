## 范围与合同

分镜元素新增独立 `production` 嵌套 Y.Map。`selection` 持久化明确选择的试做镜头与交付序列；`confirmations`、`decisions` 按独立记录 ID 保存，每次确认／决策修订追加条目。生产记录不写入 `params`，不改变生成输入 hash、候选采用或任务状态。

内容确认保存完整规范化分镜 JSON、显示版本标签、稳定分镜与画布作用域、实际 UI 操作人、来源及时间。当前确认必须同时匹配完整内容、画布 ID、分镜 ID，且不是显式历史。内容改变后旧确认待重新核对；同一稳定身份恢复原内容可重新显示原核对。删除后同名分镜或同镜号不继承确认。

决策按类型与对象分组，当前值按时间再按 ID 的稳定顺序取最新记录；本地追加时间至少比已见记录大 1ms，避免同毫秒连续修改造成当前版本倒退。跨客户端同时追加保留双方条目，同时间用 ID 决定稳定显示顺序，不声称这是跨设备真实先后时间。

代表镜头的候选可用结论继续复用已有 `creativeReview`，没有新建第二套审片系统。内容核对、实时生成授权、候选采用和交付确认保持独立。记录对象没有审批 token 或执行状态，也没有从历史续发任务的入口。

## 持久化与兼容

- schema 升至 7；v6 迁移只给分镜创建空生产结构，不猜测旧批准。未来 schema 继续只读打开，旧客户端因此不能用不识别的复制／模板逻辑静默丢掉新增历史。
- `boardId` 和收起状态仍为本机查看偏好。旧本机试做／序列选择保留为查看 fallback；新的明确选择写入当前分镜文档并优先读取。旧 `reviewedPlans` 被忽略，不升级成人工确认。
- 复制／模板导入保留原作用域和快照，并明确标记历史；只映射确实一同复制的序列 ID，外部序列不按名字重绑。镜头 ID 沿用复制分镜已有的稳定镜头身份。
- 检查点恢复保留历史原文，新画布作用域不匹配，因此原确认不成为当前确认。项目包导入在无 ID 冲突时可能保留原画布 ID；后续独立复核已纠正早期相反假设，导入明确为确认／决策逐条标记历史，见下方重开记录。scope、操作者和完整内容原样保留。
- 真实 UI 保存时即时读取当前 session principal，viewer／只读文档不能保存。通用 `ElementPatch` 和 Agent capability 没有正式生产确认写入口；布尔 `humanApproved` 不能变成有效确认。
- 每次保存和明确选择分别形成原有 `LOCAL_ORIGIN` 的一步撤销；撤销追加会移除此可见条目，重做恢复同一 ID，其他客户端追加仍保留。这是协作来源记录，不是防篡改审计账本。

并发保证的前提是同一生产结构的共同祖先。实际在线路径中，`NodeRuns` 的 `rooms.onLoad` 同步执行 `withDoc`／`createDoc` 迁移，`Rooms.get` 返回以及 WebSocket `join` 之前已经完成初始化；旧 schema 本机缓存等待服务端完整同步后才打开。集成测试覆盖持久化 v6、卸载重载、在 join 前检查初始化，再克隆两个客户端首次并发追加。没有把任意离线分叉 v6 各自创建结构解释为可自动合并的迁移合同。
