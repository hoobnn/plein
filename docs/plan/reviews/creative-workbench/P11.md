## 开工时已核实的机制与缺口

- `packages/nodes/src/sequence.ts` 的 `SequenceClip`、`arrangeSequence` 以 source 节点作设置和顺序 Map 键；`SequenceSubtitleCue.source`／`subtitleSource` 也主要用该身份。复制一个数组项会发生覆盖，不能构成独立实例。
- `SequenceEditor.tsx` 的 `rowKey`、`settings`、`patch`、拖动前后校验以 source 为键；`scene.ts` 按 assetId 出现序号建解码 key。它们都需要使用稳定实例身份。`sequenceTimeline` 已统一修剪、速度、重叠、对白与字幕时间；继续复用。
- `sequenceSpec`、本地 compose、SRT 和 `interchange.ts` 已共用既有时间及混音规则。现有 ComposeSpec 没有实例出处；`DeliverySource` 仅有 source／shotId／成片区间，`DeliveryReview` 在重叠区间用 `find` 只取第一来源，不能表达两个来源。
- `NodeRuns.collectInputs` 会为实际输入值记录 WeakMap 候选出处，能区分同节点多个端口；`freezeDeliveryOrigins` 最终却按 source 节点压成一份。需在冻结时保留具体端口／候选／实例，不能完成导出后再读当前采用项。
- `StoryboardBatches.build` 只检查叙事 shot 的独立生成节点，缺节点即 blocked。共享固定段必须纳入同一预检合同，否则缺独立 video 的另一 shot 仍无法被认作已具备素材，后续容易重复付费补缺。
- 实际项目包导入可以保留原 canvasId，不能靠“导入必换 ID”制造历史边界。P03 已修正；P11 归档必须显式处理当前映射与历史证据。

## 最小数据合同与选定方向

采用固定素材方向，复用普通 video 元素及现有序列／NodeRuns／compose；不增加执行引擎，不做一次生成多个镜头，也不让新段自动触发生成。

1. **生成段 `segmentId`**：不可变媒体身份，保存实际 `assetId`、视频种类，以及可用时的生成出处 `{canvasId,nodeId,port,resultId,runId}`。直接导入视频的生成出处为未知，不能按相同 assetId 猜候选。实际素材时长由资产元数据／probe 读取；分镜计划时长和模型请求时长仅作对比，不冒充实际长度。
2. **固定素材元素**：用户明确选定一个具体候选／端口时，可建立普通 video 元素，`assetId` 固定到该文件，独立 typed `videoSegment` 元数据保留上述出处。不把它伪装成另一个有 `params.source.role=video` 的生成节点；原节点换采用项时不替换该元素。
3. **剪辑实例 `clipInstanceId`**：`SequenceClip` 每行的持久、唯一 ID；另存当前 source 元素／精确端口、可选固定段快照、叙事 `{canvasId,boardId,shotId}`，以及该实例自己的 in/out、speed、转场、对白、字幕和声音模式。一个 segment 可被多个实例和多个序列复用；shotId、source 节点和 segmentId 均不能替代实例 ID。
4. **固定快照**：固定实例携带完整不可变 segment 值，普通 video 元素是定位视图；原生成节点或该视图删除后，实例仍保留文件和历史出处并可经现有 compose 使用。相同 segmentId 的资产／出处不允许分叉；修改固定文件必须新建 segmentId 并明确替换选中的实例。替换前列出受影响的 clipInstanceId、字幕与音轨，用户确认要保留或重新核对的设置；不把其他实例一起改掉。此快照与现有 animatic 素材快照同类，不建立会互相覆盖的第二份状态。
5. **旧 live 实例**：迁移后的原一镜一视频仍可跟随原节点的采用候选，保持旧项目行为；变化必须显示受影响的实例、字幕与陈旧状态。新建共享实例使用固定段，不把新 live 候选自动传给其他叙事镜头。

`clipInstanceId` 的复制产生新 ID；同一固定媒体段可保留 segmentId／assetId，原生成出处保持有来历的历史。当前叙事绑定与历史生成出处分别处理，不能把复制的新节点误认成原始生成任务。

## 输入与实例解析

新增纯的实例解析／校验 helper，供前端 readSequence、服务端 sequence executor、批量计划和交付共用；不各自实现另一套时间线。

- 参数内实例列表成为 v2 序列的明确顺序。live 行从精确 source+port 的实际输入读取，固定行从冻结 segment.assetId 读取。相同 source 多输出不能按 primary 或数组序号猜测；未记录端口的旧歧义必须保留并提示核对。
- 新连线到 v2 `clips` 时，在同一文档事务创建一个实例；复制实例只新增独立行，不重复连接生成依赖。先没有结果的行有稳定 ID 并显示 pending。连接、移除与映射操作可撤销；断开 live 来源不把别的输入顶替为原实例。
- 固定实例不依赖当前生成结果，原生成节点换版／删除不改变输出或唤起上游。sequence@2 的 clips 端口允许由固定参数提供素材；没有 live 输入且没有有效固定段时，执行器明确报无镜头。
- NodeRuns 仅对 `plein/sequence@2` 精确收集仍被 live 实例使用的 clips 输入，固定行不隐式沿原生成节点重新取值。其他节点尤其付费节点的 preflight、批准、提交未知与恢复合同保持原路径；对应既有保护回归列为门禁。
- 从旧 live 行改为固定时，命令明确替换选中行并处理不再使用的连线；不得留下一个未配置输入被第二次追加成隐式片段。外部新增连线产生自己的新实例，不按同名 source 合并。
- 固定段以资产 owner、实际文件可读及可探测时长校验。缺文件、无有效时长、越界入出点显示具体实例原因，不能把占位当生成成功。媒体读取等待和取消复用原序列规则。

## 旧序列与字幕迁移

开工时预定 schema 从 P06 的 10 升至 11，序列节点 `plein/sequence` 升至 2；实际按这两个版本实现。schema 门槛防止旧客户端用 source 键复制或编辑静默损坏新实例。

- 文档迁移根据持久 sequenceId＋输入 edgeId 确定性派生 clipInstanceId，按原有效输入顺序为每条原视频输入物化一行，保存精确 source 与 port；未生成输入也保留 pending 身份。旧参数中相同 source 的有效设置，按原 Map 的实际生效规则展开到对应行；孤立／坏设置保留原文待核实，不擅自新增到成片。
- 原顺序、in/out、速度、转场、原声音量、自动／明确对白和音效保持一致。原 v1 自动声音对应可保留为 `legacy` 模式，不能猜用户当时意图；新共享实例必须显式选声音路线。
- 字幕按 clipInstanceId 归属，cue 继续保存镜头内的成片相对秒数。一个实例的文本／时间／隐藏、重排和修剪操作不改另一个实例；变速或采用文件变化令相关旧字幕待核对，不擅自把人工时间当识别结果。
- 旧字幕轨的 source 唯一时映射到对应实例；同一 source 多输入时，按旧实际显示规则复制并分配独立 cue ID，保持原成片文本／时刻。未知映射保留原轨与原因，不按数组位置重新绑定。
- doc 不依赖 nodes 的运行函数。迁移可保留明确标记的 v1 字幕 inputKey，并由 nodes 的兼容比较 helper 用同一当前输入计算旧键；未发生内容变化时旧手改轨仍可预览／导出。首次真实编辑后使用 v2 键；旧键不匹配必须待核对，不能简单刷新 hash 绕过陈旧检查或静默丢掉手改字幕。
- 在途 v1 本地任务按其已持久化 PreparedInput.nodeVersion／冻结输入运行兼容迁移，不因当前文档升为 v2 而误读新参数。新冻结记录携带实际节点版本；旧记录缺版本依据时明确等待重新审阅，不能拿当前参数猜旧任务。测试覆盖 shutdown 后升级文档再恢复，以及付费任务首提交预检不被绕过。
- 迁移必须有旧／新 timeline、音轨位置和手工字幕逐值相等的金样测试，包含 `clips=[]` 仅隐式连线、同节点多输出、已删除来源及普通 animatic 回归。animatic 保持一镜一图语义，可提供其稳定 shotId 派生的实例身份；不借本项重构样片流程。

## 叙事映射、声音与批量补缺

映射事实在序列实例中：一个叙事 shot 可有多个实例，一段固定素材可映射不同 shots，多个序列可有不同剪辑方案。共用 helper 按真实 canvas+board+sequence+shot 返回明确映射；本机查看哪个面板不构成全局采用。

- BatchRequest／Plan 增加可审阅的 sequence 范围，UI 与 Agent `run_storyboard` 共用。明确 sequenceId 时只看这一个序列；只有一个有效关联序列时可确定该范围。多序列存在不同映射且调用者未指定时，返回范围阻塞并提示选择，不把其他序列的素材当本次已完成。
- video 补缺在生成节点检查前读取有效固定映射：已明确固定素材且实际文件可读的 shot 形成 `reuse` 行，显示 segment、实例、源区间、序列与零调用；即使没有独立 video 节点，也不能为此创建／提交一个新生成。映射坏数据／缺文件仍 blocked，不能降级为自动付费重做。
- 映射或声音选择属于预检签名与提交前 revision。预检后、跨 await 或排队期间变化时，不消费旧 scope 继续提交；P02 既有 TTL、只读、取消、并发一次性和 input_changed 不自动重提继续成立。
- 对固定共享映射的显式重拍，首版选择明确 `blocked` 并定位到固定源／相关实例，列出全部实际使用者；不悄悄重跑原共享生成节点。用户先显式解除所选 shot 在该序列的共享绑定或建立独立源，再走原局部生成清单；新候选是否替换某个实例另作明确操作，其他实例和序列保留原文件。
- 新共享实例要求明确选择 `native` 原生声、`voice` 独立配音或 `mix` 两者混合。native 不自动配顺序对白、不调用配音；voice 关闭该实例的原生声；mix 才同时保留二者。复用原 clipVolume／dialogueVolume／音效／配乐／duck 和 compose 音轨路径；独立配音仍按现有成片秒播放，不因视频变速擅自变声。
- native 范围的 speech 补缺行明确 skip／说明不需要独立配音；多个实例声音路线不同则展示实际需配音的实例，不把一份对白自动再分配给每个复用行。新共享行默认不顺序认领已有 dialogue/more/sfx，需明确绑定；一次确切选择某段配音不自动批准另一个实例的叠加。
- 制作总览／引导和 P07 工作台读取同一映射，区分“已有固定素材”和“存在可重拍生成节点”。固定段复用不自动制造对应叙事范围的创作验收或 P06 运动／声音观察，旧候选原审片不升级为新片段已人工核验。

## 同一时间转换与交付出处

继续以源素材秒为 in/out、成片秒为 start/end，`length=(min(out,actualDuration)-in)/speed`；转场由 `sequenceTimeline` 原规则限制与排布。所有时间使用有限秒数与左闭右开区间，末帧定位沿用原容差，不按节点 ID 去重两个实例。

- 预览 frame key、选择／拖动／修剪草稿 key、字幕归属、设置 patch 都改为 clipInstanceId。音频解码 buffer 可按 asset 去重复用，但每次播放的 offset／gain／route 独立，不能把 buffer 共用误作声音实例共用。
- sequenceSpec 为每个 ComposeClip 附可选 typed 出处，承载 clipInstanceId、segmentId、assetId、叙事 scope、精确 source／port、原候选 resultId／runId、源入出点、speed 和成片区间；元数据不改变合成引擎。服务端冻结使用实际本次数据，不能完成后从当前 doc 或同 assetId 推测。
- DeliverySource 增加以上可选字段，旧记录继续可读并明确未知；DeliveryNote 可绑定具体 clipInstanceId。成片某时间的来源查询必须返回所有覆盖实例，重叠区间不得用第一条来源代替完整关系。源时刻为 `sourceIn+(filmTime-start)*speed`，不得只做加法。
- MP4、SRT、OTIO、FCPXML 均使用同一 spec/timeline。工程 ZIP 另带版本化 `clip-map.json` 保存完整实例及时间变换；OTIO 的已有私有 metadata 同样携带身份。FCPXML 的原时间规则保留并校验；不依赖剪辑软件识别私有 ID，sidecar 始终可回溯。新 metadata 不新增 Provider 入口。
- P12 的实际 subtitleEvidence 继续取本次 executed spec，不能用当前字幕回填旧报告。更改剪辑不改旧交付／技术检查记录，输出新版本后旧确认与报告维持历史。

## 复制、模板、恢复与文件保留

- typed 复制 helper 为新 sequence 的实例及 cue 分配新 ID，按明确映射更新其内部引用、顺序和 subtitleKey。source／port／叙事 board 引用只重映射真正复制的目标；外部引用保留原身份并显示历史／未绑定，不借同名对象复活。固定资产和生成出处不被自由文本 ID 替换。
- 固定段不可变值可在多个副本复用；新当前叙事绑定必须对应目标 scope。模板实例化／复制保留可编辑设置，不携带实时 token、执行授权或新叙事范围的人工观察。
- 检查点恢复及 `.plein` 当前／全部历史包都保留固定段与实例，导入即使保留 canvasId 也明确历史化原审核／观察／检查报告；P03／P05／P06 已有归档 helper 不回退。可编辑剪辑身份和旧交付历史身份分别保留，不能把历史交付映射重写成新草稿。
- `documentReferences`、项目包收集及 checkpoint 使用 typed 固定段资产强引用扫描；不能只依赖 params 中任意字符串的弱扫描。删除原生成节点、固定素材视图、换采用项后，实例／历史交付／检查点仍引用的文件不被 GC。删除全部引用后按现有保留期回收，不强删共享内容地址文件。
- 实例来自无生成出处的旧媒体时保留 unknown。来源元素删除不使同名新元素接管历史；文件缺失时允许查看文本出处，导出明确失败而不是悄悄提交模型补回。
