## 数据合同

`board.production.continuity` 预建 `subjects`、`plans`、`observations` 三个独立子 Map。元数据不进入生成参数或输入 hash，不改变采用项、不触发模型。

主体有独立 `subjectId` 和可选的 `elementId/libraryId` 绑定。名字仅作显示，同名主体不合并；未绑定、绑定失效或撤销后的主体不按名字重连。角色、场景、道具均可只选择需要记录的部分，不要求填写全表。

不可变 `ShotPlanRevision` 保存稳定镜头 ID、父版本集合、实际 UI 操作人、时间和捕获范围。`content` 包含可选 `intent`、手填起止状态、明确继承与 reset。镜头目的与实际画面 `description` 分开，P07 可直接调用 `updateShotIntent`，保留已有状态并用 `expectedHeads` 防止迟到覆盖。

状态的世界位置、画面位置、姿态、道具持有者与手、完好程度分别存储。持物字段只能由道具引用已登记的确切角色；左右手是明确值，未知不靠同名补齐。

后镜引用 `fromShotId/planRevisionId/subjectId/fields`，读取冻结版本的结束字段。后续修订只比较明确引用的字段值；目的、未引用主体和其他字段变化不向该依赖误报。源计划存在协作分支时，只有所引用字段出现分歧才向后镜报告分歧。主体或引用缺失保留未知，不改成另一位同名主体。时间跳跃、独立场景和插叙显式 reset，清除当前继承；旧继承值不会自动变成手填值。

计划追加按记录 ID 保存，并发从共同父版本产生的多个 heads 全部保留。没有唯一 head 时不选择“最新真值”，用户明确选择草稿内容并保存合并版本。保存携带所见 `expectedHeads`；迟到编辑拒绝写入。内容完全相同的再次保存不制造新版本。

## 观察与检查范围

观察独立绑定画布、分镜、镜头、节点、具体 `CreativeReviewTarget(assetId/resultId)` 和起始／结束检查方向。相同 assetId 的新 resultId 也不继承观察。旧观察保留为历史，当前节点重新指向其他镜头时不会借用原观察。

每个字段分别记录 `observed`、`unknown` 或 `inferred`；没填字段表示没检查。未知不能夹带 value，推测不能显示为已核验。工具来源必须引用现有具体结果，并且只能产生未知或推测；本项 UI 只记录人工声明，没有自动状态提取或模型调用。

静帧保存实际派生图片 ID 和首帧、末帧或已知请求点。`last=true` 记录为末帧，不编造精确 PTS。静帧只能声明视觉样本，不能保存完整动作或声音检查。区间来自现有 `CutLoop` 的实际播放器范围，只有 native `played` 覆盖该段后才启用区间选项；用户还需显式声明检查项目。静音回放不能记录声音检查。区间和确定性分别显示，不把一个范围声明写成所有字段均已核验。

UI 复用现有连续性真实抽帧、切点回放和 `CreativeReviewForm`。新观察不自动写回计划，也不写“可用”结论。已有创作验收与计划确认继续独立；复用表单补齐当前 session、viewer 和当前文档守卫。

删除生成节点或淘汰旧结果后，观察仍保护原证据；删除整份来源记录后，已命名检查点仍保护其冻结证据。缺失资产保持缺失，不按名字找替代物。普通观察不会改变候选采用或再次提交。
