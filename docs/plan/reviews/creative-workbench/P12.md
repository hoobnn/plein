## 固定数据与执行合同

请求冻结 `{canvasId, boardId, sequenceId}`、`deliveryId`、原导出 `runId`、`resultId`、源 `assetId` 和目标不可变修订 `id + snapshot`，可选字幕证据另带同一输出 `assetId/resultId`。目标缺失、并发未合并或分镜选择不明确时不准备执行；同名或已删除对象不借用旧身份。

报告存为检查节点 JSON 结果；源视频必须由当前用户实际读取，并核对磁盘内容 SHA-256 与资产 ID 一致。JSON 内不放原始逐帧 PTS 数组，只保存有界标量与区间。`deliveryCheckAssets` 只识别完整有效的本类型报告，明确保留源视频，不用自由字符串猜资产。

“当前报告”同时要求检查结果已采用、非复制／导入／恢复历史标记、实际序列采用输出身份匹配，以及当前目标修订和规范快照精确匹配。目标或实际输出换版后旧报告只供历史查看。报告不写 `Delivery.confirmedAt`、不撤回或新增人工确认，不改变生成参数、采用项、其他镜头或模型授权。

复用 NodeRuns／JobStore 的既有作业队列和冻结请求恢复，通过 PluginHost 的可选 `MediaService.checkVideo` 与 `withMediaAbort` 执行。P12 的一个处理槽独立于 P08：两种功能可以各运行一个作业，不能据此声称全局只有一个媒体任务。

打开／查看零执行；点击明确的“执行免费本地技术检查”才创建检查节点和请求。异步输入预检完成后再次核对 engine、canvas、序列视图、对象、输出、目标、权限和实时只读，调用既有 `runNode` 并带输入 hash。取消复用既有作业接口。检查节点是本地 job，没有 capability／Provider 调用。

## 技术规则与产品上限

规则版本固定为 1：时长容差 0.05 秒；FFmpeg `blackdetect` 的最短区间 0.5 秒、像素阈值 0.1、画面比例阈值 0.98；`silencedetect` 的阈值 −50 dB、最短区间 0.5 秒。报告带实际 FFmpeg 版本和这份规则；参数含义参考 [FFmpeg 官方过滤器文档](https://ffmpeg.org/ffmpeg-filters.html)。

输入最多 600 秒、512 MiB、最长边 4096、最多 1,000,000 个解码帧；单作业总截止 10 分钟；报告最多 512 KiB；每类候选／缺样本区间最多 1000；字幕计划最多 5000 条。执行入口核对实际文件／元数据，流式解码中复查帧数、时长、实际尺寸与日志边界，发布前核对报告大小。没有输出转码或临时媒体文件。

首个实际解码视频 PTS 定义为显示零点。保留原始首／末视频 PTS、实际末帧持续时间、首／末音频样本 PTS；候选区间相对视频零点。VFR 最后一帧缺少实际持续时间时不拿上一帧间隔猜尾长：完整解码可通过，实际时长及依赖它的字幕／黑场／静音检查保持未检查。

单音轨样本的起点、终点和内部大于 0.05 秒的缺口形成 `audioUncovered`；晚开始、早结束或内部缺样本时静音项未检查，并显示相应区间。无音轨和多音轨的静音范围也保持未检查。音轨存在仅证明轨道事实，不证明对白、原声、音乐、音效、口型或声音内容达到目标。

字幕只核对本次实际导出计划的启用状态、非空文本和区间；不排序／夹取越界数据。目标要求字幕但计划缺少，或目标明确不需要字幕而实际执行计划含非空字幕，均报告问题。旧输出无证据时未检查，不读取当前画布字幕补证。没有 OCR，也不声称烧录内容已核验。

黑场／静音始终是候选区间。明确允许有意黑场或静默的目标变体不因此报该项问题，但报告保留候选与人工核对说明。“技术范围通过”与报告附列的创作未检查项并存；MP4 容器、完整解码或重复静帧均不证明实际动作、身份与创作质量。

子进程取消先 TERM、1 秒后必要时 KILL，并等待实际 close 才释放槽；排队取消移除等待项。取消／超时不发布报告；其他解码／资源失败只能发布失败或结束为失败，不能留下部分通过报告。

## 发现、修正与证据边界

1. 流式 stderr 中音频／视频片段可能共用一行，简单 substring 曾把 20 帧记为 21 帧。改为精确视频帧记录匹配与连续序号检查，真实独立 ffprobe 帧数回归关闭。
2. root 独立提前复核发现字幕目标 `none` 与已执行非空计划冲突遗漏，和部分音轨覆盖可能被当整片静音通过；均已补真实文件回归并关闭。
3. 收尾自查发现未知尾帧时长不该用上一帧间隔估计。真实 FFmpeg 包装器仅移除时长日志，仍实际解码 20 帧；报告及依赖项保持未检查，正常检查随后恢复通过。
4. 空项目导入会按既有合同保留无冲突 canvas ID，不能仅靠 scope 变化推断历史。复制／导入／检查点均加显式历史标记并验证。
5. 早期归档测试曾在最小包之前建检查点，导致 checkpoint pin 合理保留全部资产；已调整测试顺序，分别验证 JSON 唯一引用和完整 checkpoint 保留。零调用计数改用既有 `parseCalls`，实际 journal 为字典。
6. 一次持久化测试受并行 P09 注册未落全的中间状态阻断，作者完成注册后消失；一次 web 类型检查受其测试夹具路径阻断，修正后最新类型检查通过。不把并行中间状态作为 P12 产品缺陷。
