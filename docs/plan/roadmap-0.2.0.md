# Plein 0.2.0 规划：生成可控与局部返工

2026-10-14；同日调整范围与顺序。状态：W1 已实现并定稿，W2、W4、W5（最小版）已实现（均 L1–L3 通过），其余待实施。

## 目标与依据

让用户在生成前看清实际输入，在修改后看清影响范围，在失败后恢复已有任务与产物，并能把项目迁入另一套本地安装。优先降低完成可用镜头所需的生成次数和返工操作数。

基线以 0.1.2 的源码和 [0.1.0 验收记录](acceptance-0.1.0.md) 为准：真实六镜头样例已有角色 / 场景 / 道具参考图、音色绑定、资产跨项目复用与远端任务重启续查；参考图已按模型上限先保角色、再场景和道具取舍，`@` 引用是软依赖，参考图失败时镜头只带文字设定照常生成。这些证明对应样例的流程，不代表所有模型和故障场景均已验收。

设计取向：对象身份稳定、实际输入只准备一次、批次与任务有持久记录、产物采纳与当前结果分开、成功状态分层。供应商行为以官方 API 和真实验收为准；保留 PixiJS、Yjs、SQLite 与 PluginHost，复用现有能力边界。

## 范围与实施顺序

0.1.x 负责把已经落地的功能发出去并补验收（见 [0.1.0 路线图 · 0.1.x 维护版本](roadmap-0.1.0.md#01x-维护版本)），原 W6 浏览器缓存与重连验收移到 0.1.3。0.2.0 只放新的工作包，分一条串行主线和一条并行线：

| 里程碑 | 工作包                    | 定位               | 依赖与完成判据                                                             |
| ------ | ------------------------- | ------------------ | -------------------------------------------------------------------------- |
| M1     | W1 实际输入预览与参考策略 | 发布必需（已实现） | 输入摘要字段先评审定稿；预览、缓存计算与提交共用同一份准备结果             |
| M2     | W2 影响分析与局部返工     | 发布必需           | 基于 W1 的输入摘要；修改目标镜头不覆盖其他镜头                             |
| M3     | W3 批次快照与任务恢复     | 发布必需           | 使用 W1 / W2 的执行目标；未知提交可核查，已有产物可重新获取                |

分镜组、区域编辑、取帧续镜、运镜 / 风格预设和第三方插件保留为扩展候选，主线完成后逐项验收，不作为 0.2 发布必需。社区、积分、团队权限、完整动态导演台继续后置。

## W1 实际输入预览与参考策略

### W1 用户行为

生成前可展开查看最终提示词、实际参考图及顺序、音色、模型和有效参数。显示每个引用的来源，以及只附文字、超限舍弃、参考失败和当前模式不支持的原因。

每个镜头可设置必需参考与优先级。默认沿用 0.1.2 的行为：所有引用都是可选参考，按角色、场景、道具的顺序取舍；用户可把剧情关键道具或角色设为必需，不强制每次手动排序。必需参考缺失、不可用或超过模型容量时停止该目标并给出处理选项；可选参考允许降级，降级必须进入预览及执行记录。

### 实现边界

扩展 `apps/server/src/runs/mentions.ts` 和输入准备流程，预览、缓存计算与提交复用同一准备结果。建议摘要包含来源 ID、实际资产 ID、引用策略、舍弃原因、Provider / 模型、有效参数与输入哈希；字段名和协议在实现前评审。

预览不调用付费生成。参考资产或模型参数在预览后变化时，提交前重新准备并展示差异，不执行已失效的必需参考计划。音色不兼容继续遵守现有 Provider 绑定规则。

### W1 验收

- 模型最多接收三张参考图时，用户可保留关键道具，预览顺序与 mock Provider 实际输入一致。
- 必需参考失败时该镜头不提交；可选参考失败时有明确降级记录，无关镜头继续执行。
- 改名、同名、换候选和模型切换后，预览来源与实际资产仍正确。

### W1 实现记录

- 缓存键 v2：带 `v2:` 前缀，计入实际模型（自动选择时是解析出的那个）、平台插件版本和平台声明的模型版本（`ModelSpec.version`，可选）；`usedRefs` 只是取舍结果的描述，不再计入。升级前无前缀的键按旧算法比对，旧结果不因升级整组重跑。
- 留待 W3：`expect` 只在提交时核对，排队期间输入变化不会拦下；W3 冻结批次输入时把确认的哈希随任务存下并在执行前复核。

## W2 影响分析与局部返工

### W2 用户行为

提供“查看影响”：列出修改原因、直接和间接受影响对象、建议重做的阶段、可保留的产物、缓存命中和待执行数量。有价格配置时给出估算，缺价格时标明未知。

过期表示需要审查，不等同于自动付费重新生成。用户可以保留已有结果、只改配音 / 字幕，或选择需要重新生成的分支。计划按稳定镜头 ID 关联，不按当前行号定位。

### 修改规则

| 修改             | 默认建议               | 保留行为                                         |
| ---------------- | ---------------------- | ------------------------------------------------ |
| 角色参考图       | 审查引用它的镜头图     | 原视频保留；采用新图后再选择是否重做视频         |
| 台词             | 更新对应配音与字幕     | 画面是否重做由用户选择                           |
| 采用另一视频候选 | 替换序列来源并检查时长 | 原入出点先保留；越界、对白溢出和转场问题提示处理 |
| 分镜参数         | 展示与展开节点的差异   | 手改字段继续按现有同步合同处理                   |

### W2 验收

用六镜头项目修改第三镜头，只运行用户选中的受影响分支；其他五个镜头的采用结果、配音和剪辑参数保持不变。撤销修改不删除已经生成的候选。保留过期结果的决定可见可追溯，不隐式修改缓存有效性。

## W3 批次快照与任务恢复

### 执行合同

批次启动时固定目标镜头、实际输入及资产哈希、模型参数、执行阶段和跳过原因。批次记录持久化在服务端任务层，进度留在运行时状态；文档只存必要关联，不把频繁进度写入 Yjs。

执行中编辑分镜不改本批次输入。引用尚待上游生成时，先记录待解析的依赖及版本，在目标实际提交前冻结实际输入；不能把未产生的资产写成已冻结。涉及付费且实际输入相对批准计划发生变化时重新审查。

晚返回产物进入对应执行记录与候选历史；仅在目标和输入版本仍匹配且符合既定采用规则时更新当前结果，否则保留待采用。删除节点、取消或更新输入后，晚结果不得覆盖现状。

### 恢复状态

区分远端失败、提交状态未知、远端处理中、远端成功但本地下载 / 保存失败、产物已入库和候选已采用。状态表示内部合同，界面使用可执行提示。

- 有远端任务 ID：沿用现有 journal 恢复查询，不重新提交。
- 提交响应丢失且无远端 ID：进入未知状态；有供应商查询或幂等合同才能自动核查 / 重放，否则提供人工核查入口，不能宣称保证不重复计费。
- 远端成功、本地获取失败：保留可恢复定位信息，支持重新获取和保存；结果 URL 过期时优先重新查询供应商，没有恢复能力则明确说明。
- 用户取消与远端取消分别记录；已发生的费用按供应商规则说明。

### W3 验收

用故障注入覆盖提交响应丢失、轮询中断、下载失败、保存失败、取消后晚返回和服务重启。对已经获得远端 ID 的任务，恢复时远端提交次数不增加；结果未写入本地时不显示完整完成。真实平台恢复验收沿用四层流程与调用授权。

## W4 项目包迁移

项目包包含格式版本、项目 / 画布文档、必要资产库条目、原始素材、采用结果、候选选择范围、来源记录、文件哈希和依赖清单。默认导出范围在界面说明，历史候选可选；所有导出的文档引用必须有对应文件或明确的外部依赖记录。

排除平台密钥、Agent 登录凭据、会话敏感信息和机器绝对路径。Provider / 模型 / 音色可保留标识，迁入后重新绑定可用配置；运行中任务只作为历史记录，不在新安装中自动续查或提交。

导入前校验版本、路径与文件哈希，列出缺失模型、音色、插件和素材。标识冲突时进行一致的 ID 重映射；以暂存方式校验后提交，失败不留下半个项目。项目包不替代整目录备份，也不承诺恢复供应商账户状态。

验收：迁入另一数据目录，原目录不可访问时仍可打开画布、播放素材并用本机 ffmpeg 导出；相同包重复导入的冲突行为明确；损坏、缺文件和不支持版本有可执行提示；包内无密钥及旧绝对路径。

### W4 实现记录

2026-10-14 实现，L1–L3 通过，真实平台未验收；无数据库迁移。

- 格式：单文件 zip（`.plein`），协议在 `packages/protocol/src/project-package.ts`。`manifest.json` 记格式名与版本（当前 1）、候选范围（`current` / `all`）、项目、画布（文件路径、SHA-256、字节数）、素材（资产 id 即内容哈希）、资产库条目、运行记录文件、依赖（模型引用、音色 `{provider, voiceId}`、节点类型与版本及提供插件）和导出时就缺的素材 / 条目（`missing`）。文件只有 `canvases/<序号>.yjs`、`assets/<sha256>`、`history/jobs.json` 三类位置。
- 导出：`apps/server/src/projects/package.ts` 在文档副本上裁剪结果（默认只留每个节点当前采用那次运行的结果），运行中 / 排队状态改成已取消的历史；运行记录不带调用日志（远端任务号、结果地址），错误信息和运行状态里的数据目录、用户主目录换成省略号。素材只带自己名下且文件在的，资产库条目带归属本项目的和画布卡片引用的。fflate 流式写包，没有 zip64，单包上限 4 GB。
- 导入：先上传到数据目录 `tmp/` 下的暂存区，校验 zip 结构、条目路径（越出包目录或不在约定位置即拒绝）、清单、格式版本、每个文件的大小与哈希、文档能否解析，返回预检；确认后素材按哈希进内容存储，其余记录在一个 SQLite 事务里写入，失败整体回滚、暂存区删除。id 与本机冲突时换新并同步改写文档参数里的引用、运行状态和结果的 `runId`；本机已有同一个项目（同一个包再导入，或导回原目录）时作为「副本」导入，项目、画布、项目自己的条目、任务全部换新 id；不属于这个项目的资产库条目（全局或别的项目的）本机同一所有者已有同 id 时直接复用，不重复添加（2026-10-14 确认）。运行记录迁入后只作历史，`recover()` 不会续查。
- 接口：`GET /api/projects/:id/package/summary`、`GET /api/projects/:id/package`（`?history=1` 带全部候选）、`POST /api/project-imports`（包文件为请求体，返回 `ProjectImportPreview`，错误码 `not_a_package` / `unsupported_version` / `corrupt` / `unsafe_path` / `missing_file` / `hash_mismatch` 为 422）、`POST` / `DELETE /api/project-imports/:token`。
- 界面：首页「导入项目包」与项目卡片上的导出按钮。导出对话框说明包含与不包含的内容、数量和大小，可选「包含历史候选」；导入对话框列出数量、是否作为副本、未就绪的模型 / 节点、音色（需确认）、缺失素材与说明。
- 测试：`apps/server/src/projects/package.test.ts` 覆盖默认范围与历史候选、依赖清单、包内无密钥和数据目录路径、缺失记录、迁入另一目录（原目录改名不可访问）后打开画布与读取素材、重复导入的副本与 id 重映射、运行中状态转历史、写入失败回滚，以及非 zip、无清单、高版本、缺文件、内容被改、截断、路径穿越的提示；有 ffmpeg 时迁入后用迁入的镜头视频运行序列节点合成 MP4。`e2e/projects.spec.ts` 覆盖导出下载与再导入为副本。
- 未覆盖：音色是否仍在平台账户里只能生成时确认；插件节点按类型与版本比对，不校验插件来源；超过 4 GB 的项目需要整目录备份。

## W5 Agent 修改方案

Agent 面对“让第三镜头更紧张”等请求，先给出目标 ID、修改字段、保留项、实际参考、执行阶段和预计调用数量。用户可只应用文字修改、只生成候选图或批准完整方案。

计划绑定目标对象及输入版本，批准后变更需重新检查。内置 Agent、本机 CLI 与 MCP 共用文档命令和能力接口，所有模型调用经过 PluginHost；不为 Agent 单独建立一套模型、引用或任务实现。

0.2.0 只要求最小版：方案预览与按范围批准（文字修改 / 只出候选图 / 完整方案），对话内的逐项编辑方案等完整交互可放到 0.2.x。

验收：只批准文字修改时付费调用为零；仅批准第三镜头时不能运行其余镜头；批准后目标变化时不会执行旧计划；整轮文档撤销保留实际任务及费用记录，不能把撤销写成供应商退款。

### W5 实现记录

2026-10-14 实现最小版，L1–L3 通过，真实平台未验收；对话内逐项编辑方案留到 0.2.x。

- 协议：`packages/protocol/src/edit-plan.ts` 的 `EditPlan`。`EditTarget` 是要改文字的目标节点：稳定镜头 ID（`shot.id`，镜号只用来显示）、字段前后值 `EditFieldChange`、改完后实际送入的 @ 引用（W1 的 `InputRef`）和阻断 / 提示；`EditStep` 是批准后要运行的节点，带执行阶段 `image` / `video` / `speech` / `other`、最小批准范围 `images` / `full`、来自哪些目标、W2 的原因、能否沿用已有候选和价格；`EditKeep` 列出同一镜头里保留不动的节点及原因，`untouched` 是方案之外不受影响的结果数；`estimate` 按 `text` / `images` / `full` 给出调用次数、沿用数和费用，缺价格计入未知。目标和步骤都带 `EditBinding`（节点参数哈希 + 提出时的 `inputHash`）。会话条目新增 `edit_plan`，确认接口的请求体改为 `DecideAgentApproval`（`allow` + 可选 `scope`）。
- 服务端：`apps/server/src/runs/edit-plan.ts` 的 `EditPlans`。提出方案时复制画布的 Y.Doc，在副本上套用文字改动，用 `ImpactAnalyzer.analyzeDoc`（W2，新增的只读入口）算出目标和下游（含 @ 引用）里要重做的节点，用 `NodeRuns.inspect` 取改完后的实际输入；不写画布、不调用平台。没有模型的本地加工（如序列导出）不进方案，列为保留。方案存在内存里，一小时后过期。
- 批准：`text` 只写文字，不碰运行队列；`images` 只运行方案里的图片步骤，`full` 运行全部步骤，都交给「查看影响」同一套 `runImpact`（只跑列出的节点，能沿用按新输入生成过的候选就不调用平台）。执行前重新检查所有绑定对象，参数或实际输入（含引用的设定卡、参考图）变了就标成 `stale`、列出变了的对象，不写文字也不运行；方案只能执行一次。`only` 可只批准部分目标（目标节点 id 或镜头 id），只运行这些目标波及的节点。
- 三种入口：`propose_edit` / `apply_edit_plan` 是 `apps/server/src/agent/edit-plan.ts` 里的普通服务端能力，和其余能力在同一个注册表里，内置智能体、本机 CLI 与对外 MCP 拿到的是同一份；模型调用都经运行队列和 PluginHost，没有另建模型、引用或任务实现。会话里（内置与 CLI）`propose_edit` 直接出方案卡片，卡片本身就是确认单，用户选范围后服务端执行，模型用 `await_approval` 取结果；模型绕过卡片自己调用 `apply_edit_plan` 生成时按确认策略先问。对外 MCP 由外部应用自己确认范围后调用 `apply_edit_plan`。
- 撤销：执行时写文字用会话的 origin，记进这一轮的改动集，运行记作一次整组运行；整轮撤销回退文字、取消还在跑的运行，已提交的任务记录和生成的候选都保留。改动条的提示写明“已提交的生成任务和费用记录会保留，撤销不会退还平台费用”，撤销后显示“已提交的任务和费用记录保留”。
- 界面：智能体对话里的方案卡片列出目标（第几镜、字段前后值、实际参考和问题）、出候选图的节点、完整方案还会运行的阶段、保留项，以及三种范围的调用次数和费用；按钮为「不用了」「只改文字」「只出候选图」「执行完整方案」。执行后卡片显示已执行的范围和运行的节点数；目标变了时显示变了的对象，请小满重新检查。
- 测试：`apps/server/src/runs/edit-plan.test.ts` 用六镜头项目覆盖方案字段、只批准文字修改时任务数不变、完整方案只运行第三镜头的图和视频且其余镜头的采用结果不变、只出候选图并只批准第三镜头、批准前改目标参数或引用的角色设定时不执行、会话里卡片按范围批准后整轮撤销保留任务记录和新候选；`e2e/agent.spec.ts` 用 mock 智能体出方案卡片、只改文字、整轮撤销。
- 已知限制：方案只改节点参数，分镜表本身的修改仍走同步合同，展开节点没同步的列为保留；方案不重新导出序列；服务重启或一轮对话结束时还没批准的方案作废，要重新提出；没有内置价格，费用显示未知。

## E1 静态 3D 构图实验

限定为简单场景、人物占位、基础姿态、机位与截图。构图截图作为不可变参考资产入库，来源记录场景、相机和版本，再进入 W1 的输入预览。旧截图引用不随场景编辑改变，重新截图产生新资产。

暂不扩展 Gaussian、手机 WebRTC 运镜、复杂动作、完整时间轴和专用 DCC 插件。Three.js 编辑区域独立挂载，继续复用现有画布与资产系统。

采用同一组镜头比较文字描述与 3D 参考，记录构图接近程度、人物位置与遮挡、达到可采用结果的生成次数，以及摆场景时间。控制模型和参数，记录成本与失败样例，人工审片标准在实验前确定。只有重复创作显示净收益，才规划动态轨迹 / 视频输出；编辑器运行通过不代表生成模型严格复现空间。

## 架构合同与发布指标

执行输入可追溯、已有结果可复用；本地确定性加工在固定实现和输入下可重现，远端生成保留实际产物与调用记录，不承诺相同 seed 必得相同结果。

缓存键需覆盖节点 / 适配器版本、有效参数、实际输入内容哈希和可取得的模型版本；模型名称不等于不可变权重版本。缓存命中表示沿用已保存结果，主动重新生成仍产生新候选。改造时通过版本化使旧缓存失效或显式兼容。

| 指标                   | 记录方法                                                   |
| ---------------------- | ---------------------------------------------------------- |
| 完成可用镜头的生成次数 | 按镜头统计付费提交、候选和人工采用；区分素材准备与镜头生成 |
| 局部返工操作数         | 固定六镜头案例，从改第三镜头到采用替换完成记录操作         |
| 失败恢复时间           | 按提交未知、轮询、下载、保存四种故障记录恢复耗时与提交次数 |
| 迁移成功率             | 固定包集在新目录导入、素材校验与导出，损坏包另记拒绝结果   |

先在 0.1.2 上记录当前基线，再于各工作包验收时对照，不以模型数量、节点数量或未经测量的百分比作为成功标准。0.2 发布必须交付 W1–W4 与 W5 最小版，W5 完整交互、E1 与扩展候选不阻塞发布。

L1–L3 与必要 L4 沿用 [四层验收流程](acceptance-0.1.0.md)。每个工作包记录实现版本、对应测试、运行证据、真实平台范围和未验收项；除已标注的 W1 外，本文其余工作包保持“待实施”，验收后再更新状态。
