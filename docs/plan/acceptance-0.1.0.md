# 0.1.0 验收流程

2026-10-12 起，roadmap 的每个实现都按本文件的四层流程验收。目的是让「源码存在」和「真的能用」分开：代码合并不等于能力交付，每一层都要留下证据。

## 为什么分四层

roadmap 第三节已经写明，流程验收与成片质量验收要分开记录。这里再具体化：

- 单测能证明数据关系和分支逻辑，证明不了 ffmpeg / 平台接口 / 界面点击。
- mock 平台能证明画布编排与任务调度，证明不了真实模型的输入是否生效。
- 真实样例要花钱、要人看回放，不能作为每次改动的门禁。

所以每层有明确的准入和结论写法，缺哪层就写「未验收」，不许含糊过去。

## 四层流程

| 层          | 做什么                                                                                      | 门槛                                                           |
| ----------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| L1 单元     | 纯函数：差异计算、参数校验、ffmpeg 参数拼装、缓存键                                         | 新增逻辑有对应用例；边界与错误分支有用例                       |
| L2 集成     | mock Provider（`PLEIN_MOCK_PROVIDER=1`）跑通节点运行、缓存、导出；媒体加工用本机真实 ffmpeg | 端到端状态与产物断言通过，不靠日志人工判断                     |
| L3 运行冒烟 | 真实起服务，按用户路径点一遍（见下）                                                        | 关键路径可用；失败有可执行提示，不是 cryptic 报错              |
| L4 真实样例 | 真实平台调用与人工回放                                                                      | **需要用户授权与密钥**，默认不做；未做就写「未验收（待授权）」 |

L1–L3 是合并门禁，L4 是发布门禁。mock 通过不能替代 L4，这一点 roadmap 第二节已经写明，不再重复。

### L3 运行冒烟的固定路径

```bash
pnpm e2e            # 自动化部分：构建 e2e 前端，用 mock 平台起真服务，Playwright 点完下面 1–5 步
pnpm dev            # 手工走查时用：服务端 + 前端
```

`pnpm e2e` 首次运行前要装一次浏览器：`pnpm exec playwright install chromium`。

1. 首页新建画布，导入一张图片、一个视频、一个音频、一段 Markdown；
2. 设置页启用 mock 平台（开发时用 `PLEIN_MOCK_PROVIDER=1`），跑通文本 → 图片 → 视频 → 配音 → 配乐；
3. 跑一遍本次交付的用户路径（例如「展开分镜 → 批量出图 → 导出 MP4」）；
4. 刷新页面、停掉服务重启，确认元素、资产、引用、任务记录都还在；
5. 制造一次失败（例如选一个没配密钥的平台），确认节点上给出可读的失败原因。

第 4、5 步是 roadmap 对 0.1.0 的硬要求（「刷新 / 重启后不丢」「失败任务能明确恢复或核查」），每次验收都要真的做，不能只跑单测。

## 环境差异必须如实记录

本机 ffmpeg 是 Homebrew 构建，**不含 libass**，`ass` 滤镜不可用；Docker 镜像里有。涉及字幕烧录的验收：

- 有 libass 的机器：跑完整导出断言；
- 没有的机器：跑「关掉字幕也能导出」的结构用例，并验证「要字幕时提前报可执行错误」。

不允许把跳过（skip）写成通过。`apps/server/src/assets/media.ts` 的 `mediaCaps()` 就是为此存在的：缺能力要在合成前说清，而不是让 ffmpeg 抛一句 `Error parsing a filter description`。

### E1-4 基础媒体加工

源码已实现，L1–L3 通过（含真实 ffmpeg）；**界面点击未验收**。

- 加工能力集中在服务端 `deriveAsset()`，前端工具条与 Agent 共用：`POST /api/media/derive`，产物永远是新资产 + 旁挂来源记录，源资产字节不变（「源视频一个字节都没动」用 sha256 比对）。
- 图像坐标按显示像素（含 EXIF 方向）：「裁剪：矩形坐标对应实际像素」「orientation 6 的图显示为 20×40」。
- 变速音画同步：`setpts` + `atempo` 串联；并修掉一个真实缺陷——`setpts` 不改最后一帧时长，变速后会多出约两帧导致音画错位，已按 `probe.duration / speed` 加 `-t` 兜底，并有回归测试（去掉修复即失败）。
- 音视频分离、任意时刻抽帧资产化、音频截取 / 切分 / 变速都有对应测试。
- 降级如实说明：本机 ffmpeg 无 `rubberband`，保音调变速退回 `atempo` 串联（时域拉伸，非相位声码级），结果里带 `note` 告诉用户；**没有**用 `asetrate + atempo` 冒充保音调（那会让音高差 k 倍）。
- L3：`pnpm smoke` 里加了裁剪加工 → 新资产 16×8、源资产仍是 32×24 的断言。

`pnpm e2e:real`，真实平台、真实计费，全程 11.4 分钟通过。平台只启用阿里云百炼和豆包语音：方舟这把 Key 没开通对话和视频，MiniMax 的配乐接口在这个账号上不可用。

| 环节             | 模型 / 工具                               | 结果                                          |

| 18 句台词只有 6 句进了成片         | 展开只把每个镜头的第一句配音接进序列，序列每段也只能配一条对白 | 序列每段新增 `more`，同一镜头的其余台词依次播放；预览、导出、字幕按句处理 |
| 展开的镜头压住角色、场景卡和设定卡 | 镜头分组紧贴分镜右边放，而分镜在模板分组里、右边还有卡         | 第一次展开放在画布现有内容的右侧，之后接在下面左对齐                      |

第一轮的重启核对本身也有缺陷：调用完成后记录被整条替换，远端任务 ID 丢了，无法据此核对续跑。现在完成记录里也保留 `remoteId`。

### 发版后补齐：角色一致性与界面覆盖（2026-10-13）

看 L4 成片发现两处流程缺口：每个镜头里的角色长得不一样（角色卡没有参考图），所有台词都是女声（角色卡没有音色，配音用了平台默认的女声）。补上之后把资产库、分镜同步、模板、取消运行这几块原先没有用例的功能走查一遍、补齐用例，界面冒烟扩到 20 条。

| 问题                                   | 根因                                                               | 处理                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 镜头里的角色每张都不一样               | 生成设定卡只建卡不配图；模板的定妆图接在占位卡上，批量出图也不跑它 | 新角色卡配定妆图节点连进参考图；调度把 `@` 引用算作依赖，批量出分镜图先出 `@` 到的定妆图 |
| 所有角色都是女声                       | 角色卡没有音色，配音用了平台默认音色                               | 配音模型声明预置音色（性别、年龄感），生成设定卡时按设定挑；豆包合成 2.0 补上音色表      |
| 资产库里的角色到新项目用不上           | 生成设定卡不看资产库，同名角色重新建空卡、重出定妆图               | 资产库有同名同类条目时照条目建卡（设定、参考图、音色），本项目优先，多条指不明时不套用   |
| 资产库按性别、年龄筛不出角色           | 卡片存进资产库时不带标签                                           | 存入时按设定推出性别、年龄段                                                             |
| 音色只能手填平台和 ID                  | 没有音色表                                                         | 卡片和资产库里改为下拉选预置音色，表里没有的选「自定义」                                 |
| 输入框里按 Esc 没反应                  | 画布快捷键放过输入框里的按键，输入框自己也不处理 Esc               | 第一下 Esc 退出输入框，再按取消选中（真实缺陷，也是用例偶尔点不中元素的原因之一）        |
| 分镜差异面板的主按钮是「保留用户覆盖」 | 名字不说效果，实际是「什么都不改」                                 | 改为「同步计划改动」（主）和「不同步，按节点现状」，加一行说明                           |
| 我的模板只能存不能删                   | 界面上没有删除入口                                                 | 添加菜单里「我的模板」条目悬停出删除按钮，删除前确认                                     |

新增用例：`library.spec.ts`（存入资产库带标签和音色、按性别筛、换项目套用、同一条目不重复放）、`storyboard.spec.ts`（计划改的同步、手改过的保留）、`templates.spec.ts`（存为模板、铺回、删除；生成中途取消再重新生成）、`editing.spec.ts` 补 Esc 退出输入框。用例辅助函数改为等镜头停稳、确认取消选中、确认落点在画布上再点，6 个 worker 并发、每条重复 6 次全部通过。

### 尚未验收（需要真实环境或人工）

| 项               | 原因                                   | 谁来做                  |
| ---------------- | -------------------------------------- | ----------------------- |
| 新机器十分钟装好 | 要一台没装过依赖、没有 pnpm 缓存的机器 | 发版前人工走一遍 README |

L4 用例在 `e2e/real/drama.l4.ts`，单独的配置 `playwright.l4.config.ts`，不进 `pnpm e2e` 和 CI。它自己起停服务端：模板改成 6 镜头 → 剧本、抽取、设定卡 → 展开 → 批量分镜图 → 批量视频，等至少一个视频已提交到平台后强杀服务端再起来，核对重启前后任务记下的远端调用一致（续查原任务、没有重复提交）→ 批量配音 → 配乐 → 导出。

```bash
PLEIN_L4_DATA=<配好平台的数据目录> PLEIN_FFMPEG_PATH=<带 libass 的 ffmpeg> PLEIN_FFPROBE_PATH=<ffprobe> pnpm e2e:real
```
