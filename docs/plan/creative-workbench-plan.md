## 每一项如何单独复核

每个 `P` 项和 `D` 项都有单独编号，复核记录不得用“整批通过”代替。一次可以复核多个编号，但必须逐项写结论、依据、问题及处理结果。

1. **计划复核**：核对是否确有缺口、范围是否可交付、依赖是否成立、验收是否可观察，以及是否违反既有决定。本次完成这一层。
2. **开工复核**：实施者重读当前代码和已变化的工作区，冻结本项范围、数据合同、兼容方式、故障场景与验收步骤。独立复核者确认后再实施；若计划已被现有功能覆盖，缩减或关闭该项。
3. **实现复核**：由未承担本项实现的 Agent 或开发者检查具体差异和风险路径。实现者修正后，复核者复查；有阻塞问题就不进入依赖该项的实施或发布。
4. **验收复核**：按本项证据核对 L1–L3；涉及模型效果、真实费用或人工创作判断时，独立记录 L4。编译、mock、自动脚本动作不能代替真实创作和人工采用。

复核者给出“通过／需修订／阻塞／条件后置”，记录自己的实际身份与时间，不预填人员或人工审批。内容、依赖或验收口径发生实质变化后，只重开受影响编号的复核；纯排版修改不重开。

每项实现开始后，独立保存 `docs/plan/reviews/creative-workbench/<编号>.md`。记录必须包含：实现范围、完整 commit SHA 与相关未提交差异摘要、执行环境、复现步骤、实际结果、证据位置、缺失证据、复核人、阻塞问题及复查结果。该目录到有实际记录时再创建。

交付状态分别记录“实现”“L1–L3”“L4”“独立复核”；缺少所需证据保持待验收。依赖分两类：工程依赖要求相关合同与 L1–L3 通过；以创作收益为依据的扩展还必须通过指定 L4。待测 L4 不阻止无关的本地工程工作。

新增持久化数据的各项，必须逐项检查：旧文档与高版本只读、Yjs 并发、撤销、复制粘贴／模板实例化、检查点、`.plein` 导入导出、引用资产保留及来源删除。新身份须显式重映射，未一起复制的外部引用不能借用同名对象；执行授权不随副本继承。明确本项不涉及的检查及原因，不能仅写“沿用原实现”。新增检查应与风险相称，不为低影响文案和布局写复述实现的测试。

## A 波 执行与版本

### P01 冻结能力基线与测量口径

- **交付物**：已有能力与真实缺口清单；双人对白、动作衔接、强风格三份现有案例的固定版本；本轮测量字段与证据索引。核实已有性能和恢复失败是否影响本次基线。
- **范围与依赖**：无前置项。先整理和运行必要本地流程；不把现有 `null` 指标补成成功，不自动开始付费基线。现有运行器每例只执行 trial 单镜；P06 另定至少相邻两镜的连续场景，P11 另定同一素材至少两次使用的共享生成段场景，不能复用单镜结果推断。
- **验收证据**：记录应用基点、相关差异、fixture 哈希、模型条件、起止时间及已测范围；分开记录首次可接受镜头耗时、真实用户操作数、video submit 数、返工原因和可核对费用。未观测项保留未知。
- **单项复核**：核对是否重复已有[基线运行器](../benchmarks/creative-baselines/README.md)，submit 是否计入失败和未知提交，脚本命令是否被误计成人工操作。工程基线和真实创作基线必须分栏。

### P02 统一 UI 与 Agent 的批量预检和执行

- **交付物**：`run_storyboard` 与 UI 共用 `StoryboardBatches` 的准备、清单及提交合同；确认范围包含目标、复用、阻塞、跳过、实际输入和已知价格／未知调用。
- **范围与依赖**：依赖 P01。继续使用既有 capability、`NodeRuns`、`PluginHost` 和确认模式，不另建队列；适配 Agent 的读取、确认等待和原调用结果返回。
- **验收证据**：同一文档与请求下，UI 和 Agent 得到相同任务集合及阻塞原因；确认期间和排队后输入变化会停止使用旧方案；重复确认、并发操作、提交未知及恢复原任务不引发重复 submit。
- **单项复核**：沿两条入口追到实际提交，检查默认补缺／指定范围重生成、参考准备、令牌期限及重启失效。保留现有 `auto/rules/always` 语义；自动模式不能制造人工批准记录，`await_approval` 不重发原调用。

### P03 持久化内容确认与制作决策

- **交付物**：绑定稳定目标、具体内容版本、范围、来源和真实操作人的内容确认；另存模型／风格等制作决策的修订历史。内容确认、生成执行授权、候选采用、交付确认分别记录。
- **范围与依赖**：依赖 P01、P02 的版本与执行合同。先覆盖分镜方案和代表镜头；在现有 doc／服务存储边界内决定位置，不引入 Markdown 作为第二份事实来源。`localStorage` 仅保留布局等偏好。
- **验收证据**：刷新、重启、检查点恢复及项目包迁移可核对确认对象；等待期间修改内容不会批准新版；只使相关范围过期；新候选不继承旧候选的审片结论。旧本机 `reviewedPlans` 不自动升级成人工确认。检查点恢复、复制或副本导入只保留有出处的历史内容确认，不复制 live 审批 token、不自动恢复执行授权或续发旧任务；新范围与身份须重新绑定，并按现有模式取得执行授权。
- **单项复核**：分别核对四类确认的权限、版本绑定和失效规则；只读端不能伪造确认，协作与撤销有明确行为；历史来源不明时显示待核实。通过记录不能仅凭 `humanApproved: true` 由 Agent 自行声明。

## B 波 作品与镜头

### P04 制作目标与制作总览

- **交付物**：围绕选定分镜和序列的制作目标与总览，展示规格、内容和声音要求、代表镜头、阻塞原因、待审内容及下一步入口；项目多画布先做索引，不做全局自动调度。
- **范围与依赖**：依赖 P03。复用 `creationGuideFacts`、现有任务与交付记录；目标由明确字段和补充文字组成，不能把所有创作要求强行变成自动通过项。
- **验收证据**：多分镜、多序列、关联删除、只读、恢复任务和陈旧候选下定位准确；“已有产物／已采用／人工可用／已交付”分别展示。总览更新由实际状态驱动，打开它不自动生成或切换候选。
- **单项复核**：检查多对象选择与跨画布身份，避免从聊天文本猜进度；制作目标变更有版本与影响范围。逐一查看空态、阻塞、进行中、失败与完成界面，并保留截图。

### P05 原剧情与镜头覆盖映射

- **交付物**：固定来源文本版本、稳定事件／对白标识及其镜头映射；可定位原文，展示未覆盖、压缩、合并、范围外及新增改编提案。
- **范围与依赖**：依赖 P03；P04 提供入口。首版仅做来源定位与覆盖，不做自动因果裁判；原文移动或修订产生新版本及差异，不能悄悄重绑相似句子。
- **验收证据**：重复对白、段落重排、镜头拆并、来源删除、多个剧本和局部改稿不串身份；明确区分未读、未映射和有意范围外；保留模型草稿与人工修订，改变映射不自动重跑。
- **单项复核**：核对源文位置是否有版本依据，迁移后能否还原；抽查关键事件到镜头及镜头到事件两个方向。复制粘贴／模板实例化时，内部来源、事件和镜头按新身份映射；外部来源明确保留身份或显示缺失，不借同名原文重绑。没有足够依据的历史映射保持未知，不宣称自动覆盖率等于叙事完整性。

### P06 镜头计划状态与实际观察

- **交付物**：可选的角色／场景／道具起止状态，区分世界位置与画面位置；计划状态与采用候选的观察状态分别保存，记录人工／工具来源和已检查范围。
- **范围与依赖**：依赖 P03、P05；复用现有连续性审看。先覆盖双人对白、交接道具和连续动作，不要求所有镜头填写完整状态表。
- **验收证据**：以至少相邻两镜的本地案例检查状态继承、换候选失效和无关联切镜；真实动作衔接另做 L4。换机位不误判为换位；换场、插叙和时间跳跃可重置继承；换候选后旧观察不会充当新观察；仅看静帧不能记录为完整运动或声音已核验。继承变化只提示实际依赖镜头。
- **单项复核**：用持物换手、镜头反打、道具破损和无关联切镜分别核对。未知和推测必须保留；下一镜引用哪版状态可见，不自动把生成偏差写回剧情事实。

### P07 镜头工作台

- **交付物**：在现有逐镜审核上整合剧情来源、镜头目的、参考、起止状态、生成依据、候选与审片，提供到原画布和序列的定位。
- **范围与依赖**：依赖 P04、P05、P06。复用已有组件和编辑命令；支持未补齐映射／状态的旧项目，不以缺少新字段阻断现有工作流。
- **验收证据**：完整走一遍“发现问题 → 查看依据 → 只改目标 → 生成新候选 → 审片 → 查看下游影响”；原候选和未改镜头保留。大分镜按需加载媒体，切换和关闭释放播放器及引用。
- **单项复核**：并排核对当前镜头参数与采用候选的冻结生成参数；不一致只提示陈旧，不为对齐自动重跑。验证迟到响应、切换目标、只读和协作更新。与 P01 相同案例比较操作路径，不能只用静态截图宣称操作减少。

## C 波 参考与控制

### P08 本地拉片与可编辑拆镜

- **交付物**：本地视频的切点检测、关键帧、可选片段及原音轨提取；保存来源资产、时间基准、参数和输出关系；用户可调整切点并将素材放入现有画布。
- **范围与依赖**：依赖 P01；复用本地媒体执行和资产系统。先支持本地文件，不同时接入外部视频站；开工时明确时长、分辨率、并发、临时磁盘预算和取消规则。
- **验收证据**：真实 FFmpeg 文件覆盖可变帧率、旋转、无音轨、短片、闪帧、淡变与损坏输入；切点按同一时间基准且不越界。中断可识别并恢复或明确重做范围；清理未提交临时文件，保留被文档引用的成功资产。
- **单项复核**：检查全片时间覆盖、切割误差和处理代价，报告算法漏检范围；普通抽帧不能写成语义镜头理解。撤销、重复操作、资产去重及项目包不丢来源。

### P09 可选 AI 拉片与分镜草稿

- **交付物**：在 P08 本地结果上追加逐镜说明和整片归纳，关联时间码、采样帧、模型及分析重点；用户选择后转为独立分镜草稿。
- **范围与依赖**：依赖 P08、P05 的映射合同；复用现有文本模型执行和 P02 收敛的预检、输入冻结与确认原则，不把分析伪装成 `run_storyboard` 的媒体 role。默认关闭付费分析；成功本地拆镜不因 AI 失败重做，逐镜结果与整片归纳分别保存和重试。
- **验收证据**：mock 验证部分成功、取消、归纳失败和输入变化后的晚回结果；本地结果保留。没有音频／视频读取证据时不产生“已听取／已看完整运动”的结论；真实分析质量另列 L4。
- **单项复核**：抽查结论能否回到对应采样，区分检测事实、推测和未知；素材文字及模型分析不能变成工具指令。生成草稿不覆盖原分镜、不自动采用素材或触发后续生成。

### P10 镜头控制与模型提示词指南

- **交付物**：视角、景别／焦距、运镜、光线及保持项的紧凑控制，产生可比较、可编辑的提示词草稿；通用创作方法与按已选模型加载的指南分开。
- **范围与依赖**：依赖 P03；P07 可作为后续集成入口。复用现有分镜字段、提示词建议和创作配方，不为每个平台复制整套流程；不改变用户模型，不接入动态 3D。
- **验收证据**：原文、资产引用、参考用途、模型参数及手改内容保留；指南与当前能力冲突时按真实合同提示。修改相机与转动主体、光源位置与照射方向明确区分；换模型使不适用建议失效。
- **单项复核**：对比实际发送输入与界面意图，核对草稿过期、撤销和参数冲突。精确角度／光照效果只有真实样片能评估；模板文字不能作为模型执行精度保证。

## D 波 素材与交付

### P11 叙事镜头与生成段映射

- **交付物**：区分剧情／镜头时长、模型一次生成的段、实际素材时长及剪辑区间。首版覆盖一段素材供多个叙事镜头使用，以及原生声音／独立配音的显式选择。分开 `shotId`、生成段／候选身份与稳定的 `clipInstanceId`，字幕、顺序和区间不能只用来源节点作为唯一键。
- **范围与依赖**：依赖 P05、P06、P07；先冻结映射合同，再改批量计划与序列。原有一镜一视频仍是默认映射；多次生成拼成长镜头先不做。
- **验收证据**：同一素材至少两次使用时，分别修剪、重排和修改字幕不互相覆盖；旧序列迁移为独立实例后时间线保持一致。改变镜头顺序不误触模型，更换候选会提示相关剪辑和字幕影响。预览、MP4、SRT、OTIO／FCPXML 使用同一映射；交付记录保留剪辑实例、镜头、生成段及源素材入出点，能从成片时间回到具体源区间，避免重复 submit 或重复叠加对白。
- **单项复核**：逐一检查复用、重拍、拆并、变速、转场与配音覆盖；时间单位、入出点和段内／成片时间转换一致。工程导出本地检查与剪辑软件实际导入分开记录，旧项目往返和交付来源不能丢失。

### P12 实际成片技术检查

- **交付物**：绑定导出 assetId／resultId 的技术报告，包括解码、规格、实际时长、预期音轨、字幕区间及黑场／静音候选问题；带时间范围、检测参数和执行版本。
- **范围与依赖**：依赖 P04 的制作目标；对 P11 扩展映射的检查在 P11 完成后追加，首版本不被其阻塞。复用已有交付记录，不自动写入人工可交付确认。
- **验收证据**：本地真实媒体覆盖损坏、缺轨、字幕越界及黑场／静音；区分通过、发现问题、未检查与检查失败。允许静默作品及有意黑场，不把容器为 MP4 当作真实运动；输出换版后报告不串用。
- **单项复核**：核对检查与制作目标的关系、误报和漏检，报告绑定不可变文件。自动技术通过、模型辅助意见和人工创作验收独立；声音内容、口型、身份和完整动作缺少证据时保持未检查。

## 各波交付复核

### P13 分波创作收益与交付判定

- **交付物**：在 A、B、C、D 各波形成独立验收记录，沿用 P01 案例和计数口径；每波比较首个可接受镜头耗时、人工操作、实际 submit、返工原因及费用，不合并 mock 和真实平台指标。
- **范围与依赖**：依赖 P01 和当波准备交付的事项；不等待全部 P 项才测量。现有单镜运行器仅支撑单镜流程测量；跨镜状态、一段多镜、跨镜调用和整片质量须增加对应多镜观测，列明镜头及素材范围。真实模型／人工创作部分按已有授权执行，扩大调用范围时另按具体方案取得授权；缺授权时先完成本地证据，L4 保持待验收。
- **验收证据**：比较双方的输入、模型、参数、任务范围与观测窗口有记录；样本数、失败、超时及未知提交全部保留。若评估控制效果，使用可比较且隐藏方案标签的素材，记录人工判断依据。
- **单项复核**：在每波开工前写下该波目标、观测上限、最小有意义改善及停止／缩减条件；区分实测、估算与未观测。样本不足只能报告案例结果；流程通过不推断成片质量提升。复核意见决定下一波范围，未完成的独立本地事项可继续。

## 条件候选

### D01 项目预算预留与费用账本

- **进入条件**：P02 已通过，真实工作出现跨批次预算控制需求；价格来源与计费单位可核对，并重新确定优先级。当前保持低优先级，不成为主线依赖。
- **候选交付**：项目估算、预留、可核对实际费用及未知费用，按币种和价格版本记录，复用 SQLite 任务与调用身份。
- **单项复核**：先验证并发原子预留、重启恢复和原任务核查；未知提交继续占用待核查额度，不能因本机取消当作退款。缺账单时不伪造实际费用，不把图表或总价估算当作账本完成。

### D02 动态 3D 与视频预演

- **进入条件**：继续遵守用户暂停 [E1 实验](e1-3d-composition.md)的决定。只有用户明确恢复实验、E1 实际达标且结果经独立复核后，才能另写动态方案；本计划没有恢复实验。
- **候选交付**：届时从同场景多机位、简单相机预演中选一个最小范围；骨骼动画和复杂场景另行评估。
- **单项复核**：核对 E1 的真实调用、盲评、构图收益和人工摆场时间。脚本 dry run、3D 截图或 Toonflow 演示均不能替代 E1 达标，也不能据此将动态开发标为准备就绪。

### D03 高级合成与新增制作场景

- **进入条件**：P07、P12、相关波次 P13 通过；有现有序列无法合理覆盖的明确作品需求。每次只选择一种合成能力或一个用途配方，拆成新的独立编号并复核。
- **候选交付**：高级排版／图表合成节点，或广告／讲解／混剪之一的制作配方，复用现有资产、缓存、取消、任务和交付合同。
- **单项复核**：先核实运行时实际合同及编辑／导出路径，检查可编辑中间产物与失败恢复；避免第二套执行引擎、静默切换渲染方式及仅靠新增模板宣称质量提升。完整多 Agent 产品能力不随此项自动进入范围。
